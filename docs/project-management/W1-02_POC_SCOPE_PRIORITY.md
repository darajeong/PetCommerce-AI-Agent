## 1. 이 문서에서 확정할 내용

이 문서는 24개 Agent 각각에 대해 다음 사항을 W1에 확정하기 위한 초안이다.

- 필수 PoC인지 확장 PoC인지
- 실제·테스트·Mock 중 어떤 데이터로 검증할지
- 최소 검증 수량과 검증 주차
- 선행 Agent와 실행 순서
- 접근 제한이나 데이터 부족 시 사용할 대체 방법
- W5 제품화 판정 전까지 확보해야 할 결과

## 2. 범위와 우선순위 기준

| 구분 | 의미 | 검증 원칙 | W5 처리 |
|---|---|---|---|
| P0 필수 PoC | 핵심 MVP 흐름을 구성하는 Agent | 실제 상품 3건 이상, 동일 입력 반복, 오류와 근거까지 검증 | Go 여부를 우선 판정 |
| P1 확장 PoC | 핵심 흐름의 가치와 활용도를 높이는 Agent | 대표 사례 1건 이상 또는 확보 가능한 실제·테스트 데이터로 검증 | 결과와 잔여 공수에 따라 Conditional Go·Hold 판정 |
| P2 경량 PoC | 외부 계정·운영 데이터 의존도가 높은 Agent | 테스트 또는 Mock 데이터로 입출력 구조와 계산·생성 가능성 검증 | 실제 연동은 원칙적으로 후속 백로그에서 검토 |

> **주의:** 이 표의 P0·P1·P2는 Agent의 PoC 우선순위다. W4 작업표의 P0·P1·P2는 해당 주차의 작업 실행 우선순위이므로 서로 구분해 사용한다.

## 4. W2-W4 실행 순서

### W2 — 상품 소싱·수집·번역

1. W1-07에서 확인한 플랫폼 접근 방식과 대체 경로를 검토한다.
2. A01로 후보를 찾거나 사전에 확보한 상품 URL을 사용한다.
3. A02로 실제 상품 3건의 접근과 기본 정보·이미지·리뷰 수집을 검증한다.
4. A03으로 수집 데이터를 번역·정규화한다.
5. A04·A05는 A02 핵심 결과 완료 후 잔여 공수가 있을 때만 수행한다.
6. W2 종료까지 자동 수집 방법을 확정하지 못하면 수동 입력 또는 JSON·CSV 테스트 데이터로 전환한다.

### W3 — AI 분석·점수화

1. A02·A03의 공통 상품 데이터를 입력으로 사용한다.
2. B01과 B02를 실행해 이미지·텍스트·리뷰 근거를 확보한다.
3. B04가 상품 유형별 대형견 적합성을 평가한다.
4. B05가 B01·B02·B04 결과로 100점 점수와 등급을 계산한다.
5. B03은 대표 상품 1건으로 사람 검토가 필요한 안전·법규 항목을 구분한다.
6. B06은 B05 완료 후 잔여 공수가 있을 때 테스트 후보 5건으로만 수행한다.
7. 동일 입력 3회 반복으로 핵심 사실과 총점 변동을 비교한다.

### W4 — 콘텐츠 생성·D/E 경량 검증·E04 흐름

1. C02 상세페이지와 콘텐츠 사실성 검수를 최우선으로 수행한다.
2. C01·C03·C04·C05는 대표 상품 중심으로 생성 가능성과 제한 사항을 검증한다.
