# 1. 판정 요약

판정 값: `사용 가능` · `조건부 가능` · `사용 불가` · `확인 필요`
판정 기준: PoC 목적(임의 상품의 정보·이미지·리뷰 수집) 기준

| 플랫폼 | 공식 API | 상품 페이지 접근 | 적용 수집 방법 | 대체 경로 |
|---|---|---|---|---|
| 타오바오 | 조건부 가능 | 사용 불가 (자동 수집은 사전 서면 허가 필요, 비로그인 열람도 제한적) | 미정 (API 권한 승인 전) | 상품 URL·정보 수동 입력 → JSON·CSV 테스트 데이터 |

| 1688 | 조건부 가능 (확인된 API는 상세 URL 조회뿐) | 사용 불가 (약관상 자동 수집 금지) | 미정 | 상품 정보 소량 수동 입력 (PoC 내부 검증 한정) → JSON·CSV 테스트 데이터 |

국내 판매 채널·광고·GA4 판정은 6.1절 참조.

**1차 결론:** 세 플랫폼 모두 공식 API는 존재하지만, PoC에 필요한 "타 판매자 상품 검색·상세·리뷰 수집"을 그대로 지원하지 않는다. API 승인에는 실명 인증·심사·판매자 OAuth 승인이 필요해 W2 일정 안에 확보하기 어렵다. 따라서 W2는 **수동 입력 경로를 기본으로 준비**하고, API는 병행 확인한다.

세 플랫폼 모두 약관상 허가 없는 자동 수집을 금지하며, Alibaba.com·1688은 **수동 방식의 체계적 수집과 DB 구축**도 금지한다. 따라서 수동 입력 데이터는 PoC 내부 검증용(상품 3개)으로만 사용하고, 원본 이미지·문구의 상업적 재사용은 보류한다. 제품화 단계의 데이터 확보 방식은 W5에서 법무 검토와 함께 다시 판정한다.

**대상 범위:** WBS의 "알리바바"는 Alibaba.com과 1688을 모두 포함한다 (팀 확인).

**W2 권장:** 비로그인 열람이 상대적으로 쉬운 Alibaba.com 상품을 수동 입력 대상으로 우선 고려한다. 열람 가능 여부는 약관상 수집·저장 권한과 별개다.

robots.txt의 Allow는 약관상 수집·저장·상업적 이용 권한을 의미하지 않는다. robots.txt와 이용약관은 별도로 판단한다.

## 1.1 W2 수집 방식 정의

이 문서의 "수동"은 **사람이 직접 브라우저로 상품 페이지를 열어 보이는 내용을 입력·캡처하는 것만** 뜻한다. AI 에이전트가 브라우저를 조작해 페이지를 열거나 읽는 방식(컴퓨터 유즈형 AI 수집)은 **자동 수집**으로 본다.

| 단계 | 허용 | 금지 |
|---|---|---|
| 페이지 열람 | 사람이 직접 열람 | AI 에이전트·스크립트·브라우저 자동화가 페이지를 열거나 탐색 |
| 정보 확보 | 사람이 보이는 내용을 입력, 화면 캡처 | AI·프로그램이 페이지 내용을 읽어 추출 |
| 데이터 가공 | 사람이 입력한 데이터를 AI가 정리·번역·정규화 | — |
| 인증 | 사람이 직접 처리 | 로그인·전화 인증·보안 확인(캡차 등)을 AI가 대신 처리하거나 우회 |
| 사용 범위 | PoC 내부 검증용 상품 3개 | 반복·체계적 수집, DB 축적, 원본 이미지·문구의 상업적 재사용 |

**이미지·리뷰 사용 조건:** 아래 4가지를 각각 확인하며, 확인 전 기본값은 `확인 필요`다.

| 용도 | 기본값 |
|---|---|
| 저장 (PoC 저장소 보관) | 확인 필요 |
| AI 입력 (B01·B02 분석에 투입) | 확인 필요 |
| 표시 (화면·보고서에 노출) | 확인 필요 |
| 재사용 (상세페이지·광고 등 판매 콘텐츠) | 보류 |

**해석:**
- **AI 브라우징은 자동 수집에 해당한다.** 타오바오는 제3자 에이전트를 직접 명시하고, 타오바오·1688 법률 고지는 사용자 조작 모방을 금지한다. Alibaba.com·1688 이용약관의 "자동 장치"에도 AI가 조작하는 브라우저가 포함된다고 보수적으로 해석한다.
- **사람의 직접 열람·입력도 허용이 명시된 것은 아니다.** 세 플랫폼 모두 내부 평가용 개인 열람을 허용하는 예외 조항이 없다. Alibaba.com·1688은 수작업에 의한 체계적 수집을 금지하므로, 1.1절의 "상품 3개, 비체계적, 내부 검증 한정" 조건을 지켜야 한다. 이 조건으로도 위험이 0이 되는 것은 아니며, 제품화 단계 판단은 W5 법무 검토에 넘긴다.
- 淘宝平台规则(服务协议 §2.2로 편입)은 확인하지 않았다. 별도 자동화 규정이 있을 수 있다.

## 3.5 이용약관·자동 수집

- API 호출 횟수·제한을 우회하면 안 된다.
- 상점 데이터 수집에 판매자 권한이 필요할 수 있다.
- API로 받은 판매자 데이터는 원칙적으로 해당 판매자 대상 서비스에만 사용한다.
- 여러 판매자 데이터를 집계하거나 제3자에게 공유하는 행위가 제한된다.
- 장기간 사용하지 않은 API 권한은 회수될 수 있다.
- **공식 API 권한과 웹페이지 자동 크롤링 허용은 별개다.** API 권한이 웹사이트 자동 수집 권한을 의미하지 않는다.

관련 약관: 淘宝合作伙伴开发协议, 淘宝开放平台运营规则

**PoC 영향:** 여러 판매자의 상품을 비교·집계하는 A01·A02 용도는 운영 규칙의 집계·공유 제한과 충돌할 수 있다. 법무 관점 확인이 필요하다.

**robots.txt (원문 확인):** `User-agent: *` 기준 `/`와 `/list/*`만 허용하고, 쿼리 문자열이 있는 모든 URL(`/*?*`)을 차단한다. 크롤러별 규칙이 다르므로 특정 크롤러의 허용을 일반화하지 않는다.

**판정:** 상품 페이지 자동 수집 `사용 불가`. 수동 열람·입력은 로그인 제한 때문에 가격·옵션·리뷰 확보가 어려울 수 있다.

# 5. 1688 (1688 Open Platform)

## 5.1 API 제공 범위

공식 개발자 플랫폼: https://open.1688.com/

개발자에게 API·메시지 인터페이스·데이터 인터페이스·개발 문서·도구를 제공한다. 개인·기업 모두 ISV로 신청할 수 있으나 1688 심사를 통과해야 한다.

현재 확인된 공식 API: `alibaba.open.offer.detail.list` (open.1688.com이 아닌 타오바오 TOP 문서센터에 게재)

- 이용료 무료, 사용자 권한 불필요
- 상품명·가격·이미지·SKU·리뷰는 제공하지 않는다.

| 키워드 상품 검색 | 일반 개발자용 범용 API 확인 불가 | 확인 필요 |
| 상품 상세 데이터 전체 조회 | 범용 API 확인 불가 | 확인 필요 |

## 5.5 이용약관·자동 수집

1688 이용약관(2024, 영문, §3.2)과 법률 고지(信息限制 조항)는 다음을 금지한다.

- 허가 없이 상품·이미지·텍스트 등 콘텐츠를 복사·재배포
- 콘텐츠를 수집해 별도 데이터베이스·디렉터리 구축
- 로봇·스파이더·자동화 장치 **또는 수동 작업**으로 체계적인 콘텐츠 수집
- 서면 허가 없는 콘텐츠의 상업적 이용

Open Platform 개발자 협약의 데이터 제한:

- 허용된 목적·범위 안에서만 사용, 필요한 최소 데이터만 수집
- 사용자 데이터의 제3자 제공·목적 외 사용 제한
- 권한 종료·앱 이용 중단 시 관련 데이터 삭제 의무 발생 가능
- 위반 시 API 호출 중단·앱 종료

**PoC 영향:**
- 상품 URL을 받아 자체 크롤러로 반복 수집하고 DB에 축적하는 방식은 약관 위반 위험이 높다. → 상품 페이지 자동 수집 `사용 불가`
- 약관이 **수동 작업에 의한 체계적 수집**도 금지하므로, 수동 입력 대체 경로도 PoC 내부 검증용 소량(상품 3개)으로 한정하고 원본 이미지·문구의 상업적 재사용은 보류한다. 제품화 단계 사용 여부는 법무 검토가 필요하다.
- 핵심 문제는 데이터 확보보다 **지속 수집·상업적 저장·가공·재사용 권한**이다.

- 계정 수 제한: 사업자 등록번호당 10개, 개인 6개, 해외 업체명당 10개 — **공식 문서 미확인**, 다른 출처(커뮤니티)는 사업자 5개로 기재해 상충함
- 사업자 명의 서비스 광고는 해당 사업자 명의 계정 사용 원칙

**쿠팡 광고센터**

| 계정 유형 | 접근 방식 |
|---|---|
| 마켓플레이스 판매자 | WING 판매자 계정 |
| 로켓배송 판매자 | Supplier Hub 계정 |
| 광고 대행사·분석가 | 판매자로부터 권한 위임 |

광고 계정이 있다고 API로 광고 데이터를 가져올 수 있는 것은 아니다.

## 6.5 광고 데이터 API (기준일 2026-11-02)

### 네이버 검색광고 API — 성과 데이터 API 제공

**키 발급 조건:** 검색광고 회원인 광고주·파트너사 신청 가능. 2026-06-24 갱신된 키 발급 안내 기준 **광고 계정의 계정 책임자 권한** 필요.

1. 네이버 광고주센터 로그인
2. 검색광고 → 도구 → SA API 사용 관리
3. API 이용약관 동의 및 서비스 신청
4. 액세스 라이선스·비밀키 발급

| 항목 | 조건 |
|---|---|
| 네이버 계정·검색광고 계정 | 필요 |
| 계정 책임자 권한 | 키 발급에 필요 |
| 사업자등록증 | API 발급 필수 조건으로 확인되지 않음 |
| 광고비 집행 | 키 발급 조건 아님. 단 실제 성과 데이터는 광고 집행 후 생성 |

**조회 가능 데이터:** 캠페인·광고그룹·소재·키워드 목록, 노출수·클릭수·광고비, CTR·평균 클릭 비용, 전환 지표(보고서 유형별). 성과는 `StatReport`·`Stat` API로 조회한다. 다차원 보고서는 API로 제공하지 않으나 위 API로 유사 데이터를 받을 수 있다.

**호출 제한:**
- 공개된 고정 일일 한도 없음
- 광고주 Customer ID 기준 속도 제한, 시스템 부하에 따라 실시간 조정
- 초과 시 HTTP 429 반환, 연관 키워드 API 등은 IP 기준 제한 가능
- 과거 개발자 지원 답변의 초당 20~30회는 참고치일 뿐 보장 수치가 아니다.

**다운로드 대체:** 대용량 보고서(광고성과, 지역·시간대별 상세) 일 단위 생성, 최대 1년, RAW 다운로드 가능. 2025-10-27부터 실시간 집계로 바뀌어 클릭·전환 지표가 최대 48시간 안에 변경될 수 있다. (이 변경은 공식 문서 미확인, 대행사 자료 기준)

**API 조회 기간 (공식 FAQ-stat, 2022 기준):** 대부분의 StatReport 365일, AD_DETAIL·SHOPPINGKEYWORD_DETAIL 180일, *_CONVERSION_DETAIL 45일. 2026년 공지에 "최근 2년"으로 바뀌었다는 사용자 질의가 있어 상충하므로 확인 필요.

**판정:** 계정 `사용 가능`, 성과 API `조건부 가능` (계정 책임자 권한 + 실제 광고 집행 데이터 필요)

### 쿠팡 광고 — 공개 광고 성과 API 확인 불가

| 구분 | 용도 |
|---|---|
| 쿠팡 OpenAPI | 상품·주문·배송·정산 등 판매자 업무 연동 |
| 쿠팡 광고센터 | 캠페인 관리·성과 조회 |
| 광고 성과 API | 공개 문서에서 제공 여부 확인 불가 |

판매자 OpenAPI 키를 받아도 노출·클릭·ROAS를 API로 가져올 수 있는 것은 아니다. OpenAPI의 호출 제한을 광고 API 제한으로 혼동하지 않는다.

**다운로드 대체:** 광고센터 → 광고 관리 → 광고 보고서에서 기간·캠페인·항목을 선택해 엑셀 다운로드. 캠페인·광고그룹·상품·키워드 단위 조회, 노출수·클릭수·광고비·ROAS·CTR·전환율·키워드별 성과(맞춤 보고서의 키워드 전환 보고서) 제공. 광고 매출은 보고서 유형에 따라 확인.

**판정:** 성과 API `사용 불가` (공개 API 미확인). 대체 경로: 관리자가 엑셀 리포트를 다운로드 → PetCommerce에 업로드 → CSV·XLSX 파싱 → 캠페인·상품·키워드별 저장 → ROAS 분석. MVP는 파일 업로드 방식이 현실적이다.

## 6.6 GA4 — 공식 Data API 제공

**계정·속성:** 개인 Google 계정으로 생성 가능, 사업자등록 불필요.

| 항목 | 조건 |
|---|---|
| GA4 계정 생성 | 가능 (생성자에게 편집자 권한 자동 부여) |
| GA4 속성 생성 | 계정 편집자 권한 |
| 웹 데이터 스트림 생성 | 속성 편집자 권한 |
| 실제 데이터 수집 | 웹사이트에 측정 코드 설치 필요 |

**데모 계정:** Google Merchandise Store(웹), Flood-It!(앱·웹) 데이터를 누구나 볼 수 있다. 단 **데모 계정은 Data API로 접근할 수 없다.** 화면·보고서 학습용으로만 쓰고, API 테스트는 직접 만든 속성을 사용한다.

**Data API (`runReport`):** totalUsers·activeUsers, sessions, screenPageViews, eventCount, keyEvents, ecommercePurchases, purchaseRevenue 등 조회 가능. GA4는 사이트에서 발생한 이벤트를 측정할 뿐이며, 네이버·쿠팡의 광고비·노출·클릭을 대신 가져오지 않는다.

**연동 절차:**
1. Google Cloud 프로젝트 생성
2. Google Analytics Data API 활성화
3. 서비스 계정 생성 (사용자 계정 인증도 가능)
4. GA4 속성에 서비스 계정 보기 권한(Viewer) 부여
5. JSON 인증정보를 서버에 안전하게 저장 후 `runReport` 호출

**할당량 (Standard 속성, 토큰 기반):**

| 항목 | 기본 할당량 |
|---|---|
| Core 일일 토큰 | 200,000 |
| Core 시간당 토큰 | 40,000 |
| 프로젝트별 시간당 토큰 | 14,000 |
| 동시 요청 | 10 |
| 시간당 잠재적 개인정보 임계 처리 요청 | 120 |

토큰 소모는 행 수·측정기준·필터·기간에 따라 달라지며 일반 요청은 대부분 10토큰 이하다. Analytics 360은 별도 할당량.

**판정:** 계정 `사용 가능`, Data API `사용 가능` (본인 속성 + Cloud 프로젝트 + 서비스 계정). 단 실제 이벤트 데이터는 측정 코드를 설치한 사이트가 있어야 생긴다. PoC(E01-01)는 Mock 데이터 기준을 유지한다.

## 6.8 PoC 영향

- D01-01(W4 P0, 채널 등록 데이터 생성)은 필수 필드 변환·검사 작업이므로 **계정 없이 수행 가능**하다.
- D01-02(W4 P2, 테스트 등록)는 네이버는 개인 판매자 계정으로 시도 가능하고, 쿠팡은 사업자 인증이 없으면 업로드 파일 생성 또는 Mock 엔드포인트로 대체한다.

- 실제 계정 생성에는 **팀원 개인의 본인 인증·정산 계좌**가 필요하다. 누구 명의로 만들지 팀 결정이 필요하다.
