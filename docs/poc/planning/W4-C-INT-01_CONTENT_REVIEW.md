## 3. 분류 기준

### 3.1 네 가지 분류

| 분류 | 뜻 | 예시 (지어낸 문장) | 공개 |
|---|---|---|---|
| **사실** | 원본 사실 값(W1-04, `data_type: actual`)이나 근거가 연결된 분석 결과와 같은 내용. 숫자·단위·소재가 원본과 일치. 질문·제목처럼 주장이 없는 문장도 사실로 두고 이유에 "주장 없음"을 적는다 | "소재는 폴리아미드와 폴리에스터예요." | 공개 가능. 단 근거가 합성·Mock 데이터면 공개 불가 |
| **추정** | 원본에 그대로 적혀 있지는 않지만 원본 특징에서 이끌어 낸 일반 설명. 숫자·인증·효능 같은 구체적 주장이 없다. 근거 필드를 반드시 연결 | "뒷다리가 약한 대형견 보행을 돕는 하네스입니다." (근거: 상품명) | 검토 후 공개 |
| **금지 표현** | §3.3 규칙에 걸리는 문장. 내용이 사실이어도 먼저 적용 | "관절염 치료에 효과적입니다." | 공개 불가 → 수정·삭제 |
| **확인 필요** | 구체적 주장인데 원본에 없거나 다르거나 원본 값이 누락(`source_missing`·`manual_review_required`)됨, 또는 §3.4 규칙(인증·전문가·환경·원산지) | "무게는 0.5kg입니다." (원본 무게 없음) | 공개 불가 → 사람 확인 |

### 3.2 판단 순서

1. §3.3 금지 표현 규칙에 걸리는가 → **금지 표현**
2. §3.4 확인 필요 규칙(인증·전문가·환경·원산지)에 걸리는가 → **확인 필요**
3. 숫자·단위·소재·배송비 같은 구체적 주장이 있는가 → 원본과 모두 일치하면 **사실**, 하나라도 없거나 다르면 **확인 필요**
4. 질문·제목처럼 주장이 없는가 → **사실** (이유: 주장 없음)
5. 나머지 → **추정**. 근거 필드를 연결하지 못하면 **확인 필요**로 바꾼다.

한 문장에 주장이 여러 개면 가장 엄한 분류 하나만 적는다 (금지 표현 > 확인 필요 > 사실 > 추정).

### 3.3 금지 표현 규칙 (팀 초안)

| ID | 대상 | 예시 |
|---|---|---|
| P01 | 근거 없는 최상급·단정 | 최고, 최상, 1위, 유일, 완벽, 무조건, 최초 |
| P02 | 100% 보장류 | 100% 만족, 효과 100%, 100% 환불 |
| P03 | 의약품이 아닌 제품의 질병 치료·예방 표방 | 치료, 완치, 예방, 질환, 관절염, 통증 완화, 재활 치료 |
| P04 | 근거 없는 가격·긴급성 | 최저가, 파격 할인, 오늘만, 한정 수량, 무료 배송 보장 |
| P05 | 비교·비방 | 타사, 경쟁사, 다른 제품보다 |
| P06 | 안전 단정 | 부작용 없음, 절대 안전, 인체 무해 |

### 3.4 확인 필요 규칙

| ID | 대상 | 처리 |
|---|---|---|
| C01 | 인증·시험·특허 (KC, FDA, CE, SGS, 시험 성적) | 서류를 확인하기 전까지 확인 필요 |
| C02 | 수의사·전문가·임상·연구 결과 | 근거 자료 확인 필요 |
| C03 | 친환경·무독성·무해·BPA 프리·생분해 | 근거 자료 확인 필요 |
| C04 | 국산·국내 생산 같은 원산지 주장 | 원본 원산지 확인 필요 |
| C05 | 크기·무게·권장 체중·배송비·판매량·평점을 말하는데 원본 값이 누락 | 확인 필요 (포장 크기는 상품 치수와 구분) |
| C06 | 원본에 없는 수치, 원본 배송비가 0이 아닌데 "무료 배송" | 확인 필요 |
| C07 | 원본에 없는 소재 | 확인 필요 (소재 동의어는 A03 `MATERIALS`와 같게 유지) |

- §3.3·§3.4는 PoC용 팀 초안이며 **법무 검토 전**이다. 공정위 표시·광고 심사지침과 판매 채널 금지어 정책의 URL·확인일은 C04-02(플랫폼 제약)와 W5 법무 검토 때 보완한다. 채널별 글자 수와 금지어는 C04-02 범위라 여기서는 다루지 않는다.
- 규칙을 추가·수정하면 §12 변경 이력에 남기고, 이미 검수한 결과는 소급하지 않는다 (W1-03 §4 소급 금지).

### 3.5 공개 규칙

| 최종 분류 | 공개 여부 (`publish`) |
|---|---|
| 사실 (근거가 모두 `actual`) | 공개 가능 |
| 사실 (근거에 `test`·`mock`·출처 미상이 섞임) | 공개 불가 (합성 데이터는 판매 콘텐츠 재사용 금지, W2-A02 README) |
| 사실 (주장 없음) | 공개 가능 |
| 추정 | 검토 후 공개 |
| 금지 표현 · 확인 필요 | 공개 불가 (고정) |

"자동 공개"는 `publish = 공개 가능`인 문장만 다음 단계(D01-01 등록 데이터 등)로 사람 확인 없이 넘어가는 것을 뜻한다. `검토 후 공개`는 검토자가 확인하기 전까지 넘기지 않는다. `check`는 규칙보다 느슨한 표시(예: 확인 필요를 `공개 가능`으로)를 오류로 잡는다.

## 5. C02-02 결과 입력 형식 (정민님께 요청)

```json
{
  "source": "C02-02 결과 버전·생성일",
  "items": [
    {"product_id": "prod-w2-01", "channel": "smartstore", "section": "핵심 장점", "text": "문단 그대로"}
  ]
}
```

- 같은 열(`product_id, channel, section, text`)을 가진 CSV도 된다.
- `channel`: `smartstore` · `coupang`. `section`: C02-01의 6개 영역(핵심 장점·규격·옵션·구매 전 확인·FAQ·주의사항).
- 다른 형식(마크다운 등)으로 나와도 A가 위 형식으로 옮겨 쓴다. 이때 원문 문장은 고치지 않는다.

## 5-4. 실행 절차

```bash
python docs/poc/samples/c_int01_review.py prepare --content <C02-02 결과> --facts docs/poc/samples/W2-A02-02_PRODUCT_prod-w2-01.json docs/poc/samples/W2-A02-02_PRODUCT_prod-w2-07.json docs/poc/samples/W2-A02-02_PRODUCT_prod-w2-09.json --out docs/poc/samples/W4-C-INT-01_REVIEW.csv --summary docs/poc/samples/W4-C-INT-01_AUTO_SUMMARY.md
```

1. `prepare`: C02-02 문단을 문장으로 나누고 1차 자동 표시(`auto_label`·이유·규칙 ID·근거)를 붙인 검수표를 만든다.
2. 사람(A)이 문장마다 `label`, `label_reason`, `action`, `publish`, `reviewer`, `reviewed_at`을 채운다. 추정 문장은 `evidence_refs`에 근거 필드를 보완한다.
3. `check`로 K2~K5를 점검한다.

```bash
python docs/poc/samples/c_int01_review.py check --review docs/poc/samples/W4-C-INT-01_REVIEW.csv --summary docs/poc/samples/W4-C-INT-01_CHECK.md
```

4. 검토 담당(C)이 검수표와 점검 결과를 확인한다.
5. 수정·삭제가 필요한 문장은 정민님(C02-02)께 넘기고, `공개 가능` 문장 목록은 D01-01(진님)에 알린다.
