# 1. 문서 목적

본 문서는 WBS v1.2를 기준으로 전체 Agent의 PoC 범위, 필수·확장 구분, 주차별 우선순위, 데이터 사용 제한 및 선행 작업을 정리한다.

이 문서는 **무엇을 어느 범위까지 검증할지**를 정의한다. PoC별 세부 성공·보완·실패·보류 기준은 W1-03, AI 분석·점수화 세부 기준은 W1-05, 실행 기록 양식은 W1-06을 기준으로 한다. 해당 문서의 내용을 이 문서에 중복 정의하지 않는다.

운영 원칙:

1. 필수 PoC는 서로 다른 실제 상품 3개를 기준으로 핵심 흐름을 검증한다. 다만 이미지·리뷰 등 권리 확인이 필요한 자료는 아래 데이터 사용 제한을 우선 적용한다.
2. 확장 PoC는 대표 사례 1건 또는 테스트·Mock 데이터로 기술 가능성과 입출력 구조를 확인한다.
3. WBS v1.2의 주차별 확정·조건부·P0·P1·P2 구분을 그대로 따른다.
4. W2·W3·W4의 선행 관계는 WBS v1.2의 작업 관리 정보를 따른다. 이 문서의 작업표에도 주요 선행 작업을 표시한다.
5. 실제 데이터, 테스트 데이터, Mock 데이터와 사용 권한 상태를 구분한다.
6. 권한·약관·데이터 사용 조건이 확인되지 않은 자료를 수집·저장·AI 입력·화면 표시·판매 콘텐츠에 재사용하지 않는다.
7. 실제 실행 결과와 증빙이 없는 작업은 성공 또는 완료로 판정하지 않는다.
8. 필수 작업을 보호하고, 조건부·선택 작업은 잔여 공수와 선행 조건이 충족될 때만 진행한다.
9. W5 제품화 판정과 WBS 승인 절차를 통과한 기능만 W6-W13 제품화 범위에 반영한다.

# 2. 전체 PoC 범위

전체 24개 Agent를 필수 PoC 8개와 확장 PoC 16개로 구분한다.

필수·확장 구분은 Agent 단위의 검증 수준이며, 주차별 작업 우선순위와는 별개다. 따라서 확장 Agent라도 WBS에서 확정한 개별 작업은 해당 주차에 수행할 수 있고, 확장 Agent의 개별 작업이 P0라고 해서 Agent 전체가 필수 PoC로 변경되는 것은 아니다.

## 2.1 필수 PoC (8개 Agent)

| Agent ID | 기능 영역 | 검증 목적 |
|---|---|---|
| A02 | 상품 정보 수집 | 권한이 확인된 범위에서 상품의 기본 사실 정보와 출처를 확보하고 수동·Mock 대체 경로 검증 |
| A03 | 번역 및 데이터 정규화 | 상품 정보 번역, 가격·크기·무게·옵션의 공통 구조 변환 |
| B01 | 이미지·상품 분석 | 직접 제작하거나 사용 권한을 확보한 이미지와 확인된 상품 사실을 바탕으로 특징 분석 |
| B02 | 리뷰 분석 | 사용이 허용된 실제 리뷰 분석. 실제 리뷰 사용이 불가하면 Mock 기반 기술 검증과 실제 검증 미완료를 구분 |
| B04 | 대형견 적합성 분석 | 체형, 크기, 하중, 내구성, 안전 및 사용 적합성 평가 |
| B05 | 상품 종합 점수화 | W1-05에서 확정한 기준에 따라 가격·디자인·리뷰·적합성·판매 가능성 평가 |
| C02 | 상세페이지 생성 | 권한이 확인된 상품 사실과 분석 결과를 이용한 채널별 상세페이지 초안 생성 |
| E04 | Agent 오케스트레이션 | Agent 실행 순서, 병렬 실행, 상태, 오류, 재시도 및 승인 관리 |

### 검증 수준 및 데이터 제한

- 서로 다른 실제 상품 3개를 필수 PoC의 상품 단위 기준으로 삼는다.
- 동일 상품 반복 실행 횟수와 세부 통과 수치는 W1-03 및 WBS v1.2를 따른다.
- 상품별 이미지 5장·리뷰 20개는 WBS의 초기 권장 수량이다. 권리 확인 또는 실제 자료 확보가 불가능하면 임의로 원본을 복사하지 않고 누락 사유와 대체 데이터 유형을 기록한다.
- B01은 팀이 직접 촬영·제작했거나 사용 권한을 확보한 이미지만 분석 입력으로 사용한다.
- B02는 저장 및 AI 분석 입력이 허용된 실제 리뷰만 사용한다. 허용된 실제 리뷰를 확보하지 못하면 Mock 리뷰로 기술 흐름을 검증하고, **실제 리뷰 데이터 검증은 미완료**로 표시한다.
- Mock 데이터로 수행한 결과를 실제 데이터 검증 성공으로 바꾸어 기록하지 않는다.
- 상세 성공 기준, 정확도, 허용 오류 및 증빙 요건은 W1-03을 따른다.

### 제품화 방향

필수 PoC는 W6 이후 MVP 제품화 후보지만, 필수 분류만으로 자동 제품화하지 않는다. W5에서 WBS v1.2와 W1-03에 따른 판정 및 승인 절차를 거친다.

### 검증 수준

- 대표 사례 최소 1건을 사용한다.
- WBS에서 지정한 작업은 테스트 데이터 또는 Mock 데이터 사용을 허용한다.
- 실제 외부 연동이 불가능하면 API 호출 직전 데이터, 파일 생성 또는 수동 절차까지만 검증한다.
- 실제 데이터와 Mock 데이터의 구분 및 미검증 범위를 기록한다.
- 확장 PoC의 세부 성공 기준은 W1-03 및 해당 WBS 작업 완료 기준을 따른다.

**W1-02 완료 조건:** 필수·확장 범위뿐 아니라 W2-W4의 검증 방식, 선행 작업, 대체 경로 및 조건부 착수 조건이 WBS v1.2와 일치해야 한다. 본 문서 작성이나 커밋만으로 W1-02 공식 승인 완료로 간주하지 않는다.

**W1 선행 조건 주의:** WBS v1.2에서 W1-05는 W1-03·W1-04를 선행 작업으로 둔다. W1-05 산출물이 확인되기 전에는 B05-01의 점수 계산 및 B05-02의 등급 판정 기준이 준비되었다고 간주하지 않는다.

### W2 직접 입력 및 외부 플랫폼 대체 경로

1. **W2 시작부터 직접 입력을 기본 경로로 사용한다.** 자동 수집을 먼저 시도한 뒤 W2 종료 시점에 수동 입력으로 전환하는 방식은 사용하지 않는다.
2. 직접 입력 대상은 PoC 내부 검증용 실제 상품 **최대 3개**로 제한한다. 반복적·체계적 수집, 대량 데이터 축적 또는 상업적 데이터베이스 구축으로 확대하지 않는다.
3. 직접 입력은 사람이 수행한다. AI 브라우저 조작, 스크립트, 크롤러, 자동화 브라우저 또는 사용자 조작 모방 방식으로 상품 페이지를 열람·수집하지 않는다.
4. W1-07의 1차 조사에 따르면 타오바오·1688의 상품 페이지 접근은 W2에서 사용하지 않는 경로로 분류되어 있다. Alibaba.com은 사람이 페이지를 열람할 수 있는 것으로 조사되었지만, 약관상 수동 방식의 체계적 수집 및 데이터베이스 구축 제한이 있으므로 3개 상품의 내부 검증 범위를 넘지 않는다.
5. 위 직접 입력 경로는 플랫폼 약관의 포괄적 허가를 의미하지 않는다. W1-07의 공식 약관 근거와 확인일을 기준으로 D·A가 실제 입력·저장 가능 범위를 재확인한다. 권한이 불명확한 항목은 입력하지 않고 확인 필요 또는 Mock으로 처리한다.
6. 공식 API는 **필요한 데이터 항목에 대한 공식 API 권한과 사용 목적이 실제 승인된 경우에만** 별도 검토한다. API가 존재한다는 사실만으로 상품 검색·상세·리뷰 API를 사용할 수 있다고 간주하지 않는다.
7. 상품 페이지의 원본 이미지와 상세 문구는 무단 복사·다운로드·AI 입력·화면 표시·판매 콘텐츠 재사용을 하지 않는다. 상품명·가격·옵션·규격 등 필요한 사실 필드도 출처와 입력 방법을 기록하고, 사용 조건이 불명확하면 제외한다.
8. **B01 이미지 분석:** 팀이 직접 촬영·제작했거나 이미지 사용 권한을 확보한 자료만 사용한다. 원본 상품 페이지 이미지가 권리 미확인 상태이면 분석 입력으로 사용하지 않는다.
9. **B02 리뷰 분석:** 저장 및 AI 분석 입력이 허용된 실제 리뷰를 확보한 경우에만 실제 데이터로 검증한다. 확보하지 못하면 Mock 리뷰로 분석 흐름을 검증하고 실제 리뷰 데이터 검증 미완료로 표시한다. Mock 결과를 실제 리뷰 분석 완료로 보고하지 않는다.
10. 직접 입력으로 확보할 수 없는 필드는 사전에 준비한 JSON·CSV Mock 데이터로 대체한다. 실제·테스트·Mock 구분과 누락 사유를 W1-04 데이터 계약에 맞춰 기록한다.
11. 자동 접근·API·수동 입력의 제한 사항, 미검증 범위, 데이터 사용 권한, 수동 단계와 후속 착수 조건을 W2 산출물에 남긴다. 정책을 우회하거나 권한이 없는 자료를 사용해 완료 수량을 맞추지 않는다.

# 5. 데이터 유형·권리·증빙 관리 원칙

## 5.1 데이터 유형

W1-04 공통 데이터 구조의 구분을 따른다.

| 데이터 유형 | 의미 | 기록 원칙 |
|---|---|---|
| actual | 실제 상품·실제 데이터 | 출처, 입력 방법, 사용 권한 및 확인일 기록 |
| test | 테스트 목적으로 준비한 데이터 | 테스트 데이터임을 표시하고 실제 운영 데이터와 구분 |
| mock | 합성·가상 데이터 | Mock임을 명시하고 실제 데이터 검증으로 집계하지 않음 |

수집 방법은 W1-04의 collection_method 기준을 따르며, 수동 입력은 manual, 승인된 공식 API를 통한 접근은 실제 구현 방식에 맞게 기록한다.

## 5.2 이미지·리뷰 권리 확인

이미지와 리뷰는 저장, AI 분석 입력, 결과 화면 표시, 판매 콘텐츠 재사용을 각각 구분한다.

- W1-04의 usage.store, usage.ai_input, usage.display, usage.resale 상태를 각각 기록한다.
- 사용 권한 확인 전 기본값은 needs_review로 취급한다.
- 원본 상품 페이지 이미지와 상세 문구는 권리 확인 없이 복사·재사용하지 않는다.
- B01은 직접 촬영·제작했거나 사용 권한이 확인된 이미지만 입력한다.
- B02는 실제 리뷰의 저장·AI 입력이 허용된 경우에만 실제 리뷰를 사용한다. 그렇지 않으면 Mock으로 대체하고 실제 리뷰 검증 미완료를 명시한다.
- 사용 권한이 확인되지 않은 자료는 usable로 임의 변경하지 않는다.

## 5.3 누락·대체 기록

데이터가 없거나 사용 권한을 확인하지 못한 경우 W1-04의 누락 사유 및 권리 상태를 기록한다. 최소한 다음 정보를 남긴다.

- 상품 ID 및 실행 ID
- 출처 URL 또는 출처 확인 불가 사유
- 실제·테스트·Mock 데이터 구분
- 직접 입력·공식 API·Mock 등 입력 방법
- 사용 권한 확인 상태 및 확인일
- 확보하지 못한 필드와 누락 사유
- 후속 검증 가능 여부 및 담당자

Go·Conditional Go·No-Go·Hold의 의미와 최종 판정 절차는 WBS v1.2의 W5 작업 및 W1-03 판정 기준을 따른다.

# 9. 최종 운영 원칙

1. WBS v1.2를 전체 일정, 작업 ID, 담당자, 공수 및 선행 관계의 기준 문서로 사용한다.
2. W1-02는 PoC 범위, 필수·확장 구분, 주차별 우선순위 및 데이터 사용 경계를 관리한다.
3. W1-03은 PoC별 판정 기준, W1-05는 분석·점수화 기준, W1-06은 실행 기록 양식, W1-07은 외부 플랫폼 정책·권한의 기준 문서로 관리한다.
4. WBS의 확정 작업과 조건부 작업을 혼합하지 않는다.
5. 조건부·선택 작업은 선행 작업 완료와 잔여 공수 확보를 전제로 착수한다.
6. 실제 데이터·테스트 데이터·Mock 데이터 및 권리 상태를 명확히 구분한다.
7. 약관·권한·인증을 우회하지 않는다. 불확실한 자료는 사용하지 않고 미검증으로 남긴다.
8. Mock 결과를 실제 데이터 검증 완료로 표시하지 않는다.
9. W1-05 미완료 시 B05-01·B05-02 및 후속 B-INT-01의 기준 확정을 보류한다.
10. W5에서 승인된 기능만 W6 이후 제품화 범위에 포함한다.
11. 문서 작성·커밋·PR 생성은 PoC 실행 완료 또는 공식 승인을 의미하지 않는다.
