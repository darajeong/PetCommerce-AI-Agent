# 1. 문서 목적

본 문서는 PetCommerce AI Agent 프로젝트의 WBS v1.2를 기준으로 전체 Agent의 PoC 검증 범위, 우선순위, 검증 수준, 성공 기준 및 제품화 판정 방법을 정의한다.

PoC의 목적은 모든 기능을 완성하는 것이 아니라, 각 Agent의 기술적 구현 가능성과 실제 데이터 기반 결과 품질을 확인하고 MVP 제품화 여부를 판단하는 것이다.

이를 위해 다음 원칙을 적용한다.

1. 필수 PoC는 실제 상품 데이터를 이용해 반복 검증한다.
2. 확장 PoC는 대표 사례 또는 Mock 데이터를 이용해 기술적 가능성과 입출력 구조를 검증한다.
3. 모든 PoC는 실행 과정과 결과를 증빙으로 남긴다.
4. 실제 데이터, 테스트 데이터, Mock 데이터의 사용 범위를 명확히 구분한다.
5. 확정 작업과 조건부 작업을 구분해 관리한다.
6. 조건부 작업은 필수 PoC 일정과 담당자별 공수에 영향을 주지 않는 경우에만 착수한다.
7. W5에서 승인된 기능만 W6-W13 제품화 일정에 반영한다.
8. 실제 실행 결과가 확보되지 않은 PoC는 성공 또는 완료로 판정하지 않는다.

# 2. 전체 PoC 범위

전체 24개 Agent를 필수 PoC 8개와 확장 PoC 16개로 구분한다.

필수·확장 구분은 Agent의 PoC 검증 범위를 의미하며, 주차별 작업 우선순위(P0·P1·P2)와는 별도로 관리한다. 따라서 확장 Agent에 속하더라도 WBS에서 확정한 개별 작업은 해당 주차에 수행할 수 있으며, 개별 작업이 P0로 지정되었다고 해서 Agent 전체가 필수 PoC로 변경되는 것은 아니다.

## 2.1 필수 PoC (8개 Agent)

| Agent ID | 기능 영역 | 검증 목적 |
|---|---|---|
| A02 | 상품 정보 수집 | 실제 상품의 기본 정보, 이미지, 상세 설명, 리뷰 수집 가능성 검증 |
| A03 | 번역 및 데이터 정규화 | 상품 정보 번역, 가격·크기·무게·옵션의 공통 구조 변환 |
| B01 | 이미지·상품 분석 | 이미지와 설명을 기반으로 디자인, 소재, 구조 및 주요 특징 분석 |
| B02 | 리뷰 분석 | 리뷰 요약, 장단점, 만족 요소 및 반복 불만 추출 |
| B04 | 대형견 적합성 분석 | 체형, 크기, 하중, 내구성, 안전 및 사용 적합성 평가 |
| B05 | 상품 종합 점수화 | 가격·디자인·리뷰·적합성·판매 가능성을 기준으로 100점 평가 |
| C02 | 상세페이지 생성 | 상품 분석 결과를 활용한 채널별 상세페이지 콘텐츠 생성 |
| E04 | Agent 오케스트레이션 | Agent 실행 순서, 병렬 실행, 상태, 오류, 재시도 및 승인 관리 |

### 검증 수준

- 서로 다른 실제 상품 3개를 사용한다.
- 동일 상품은 동일 입력으로 3회 반복 실행한다.
- 상품별 이미지 최소 5장, 리뷰 최소 20개를 초기 권장 기준으로 적용한다.
- 이미지나 리뷰가 부족하면 확보 가능한 데이터를 사용하고 부족 사유를 기록한다.
- 오류 처리, 결과 품질, 처리 시간 및 AI 비용을 검증한다.
- 다른 팀원 1명 이상이 동일한 절차를 재현할 수 있어야 한다.

### 제품화 방향

필수 PoC는 원칙적으로 W6 이후 MVP 제품화 후보로 선정한다. 다만 필수 PoC라는 이유만으로 자동 제품화하지 않는다. W5에서 Go·Conditional Go·No-Go·Hold 판정을 거쳐 실제 개발 범위를 확정한다.

## 2.2 필수 보조 기능

필수 보조 기능은 독립 Agent가 아니라 필수 8개 Agent의 안정적인 연결과 운영을 위한 공통 기능이다.

| 구분 | 검증 내용 |
|---|---|
| 공통 데이터 모델 | 상품 ID, 실행 ID, 원본 데이터 및 결과 데이터 구조 통일 |
| 근거 추적 | AI 분석 결과와 원본 이미지·리뷰·상품 정보 연결 |
| 상태 및 로그 | 실행 상태, 단계별 처리 결과와 오류 기록 |
| 오류 복구 | 자동 재시도, 수동 재실행, 부분 성공 처리 |
| 관리자 승인 | 승인·반려·수정 및 이력 관리 |
| 통합 테스트 | 필수 Agent 간 데이터 전달 및 전체 실행 흐름 검증 |

공통 보조 기능은 W1-W5에서 검증하고 W6 이후 MVP의 공통 기반으로 구현한다.

주요 보조 작업은 다음과 같다.

- W1-04: 공통 데이터 구조
- W1-06: PoC 실행 기록 양식
- B-INT-01: B그룹 반복 실행 및 일관성 검증
- C-INT-01: 콘텐츠 사실 검수
- E04-01·02: 오케스트레이션 및 오류·승인 검증
- DE-INT-01: D·E 통합 보고서 구조 검증

### 검증 수준

- 대표 사례 최소 1건을 사용한다.
- 테스트 데이터 또는 Mock 데이터 사용을 허용한다.
- 기능의 기술적 구현 가능성과 입출력 구조를 확인한다.
- 실제 외부 연동이 어려우면 API 호출 직전 데이터, 파일 생성 또는 수동 절차까지 검증한다.
- 실제 운영 수준의 안정성과 품질을 입증하는 단계로 확대하지 않는다.
- 실제 데이터와 Mock 데이터의 구분을 반드시 기록한다.

### 제품화 방향

W5에서 Go·Conditional Go·No-Go·Hold 중 하나로 판정한다. 확장 기능은 필수 MVP의 일정과 품질에 영향을 주지 않는 경우에만 착수한다.

# 3. PoC 실행 우선순위 및 일정

PoC 실행은 W1-W5 일정에 맞춰 진행한다.

| 주차 | 핵심 목표 | 주요 검증 범위 | WBS 일정 구분 |
|---|---|---|---|
| W1 | PoC 설계 및 준비 | 전체 범위, 성공 기준, 공통 데이터 구조, 기록 양식 | 확정 8개 작업 |
| W2 | 상품 소싱 및 데이터 확보 | A01-01·02, A02-01~04, A03-01·02 | 확정 8개 작업 / 조건부 2개 작업 |
| W3 | AI 분석 및 점수화 | B01, B02, B03-01, B04, B05, B-INT-01 | 확정 10개 작업 / 조건부 1개 작업 |
| W4 | 콘텐츠 생성 및 시스템 연결 | C02, C-INT-01, D01-01, D02-01, E04, DE-INT-01 | P0 8개 확정 / P1 선택 / P2 축소·보류 |
| W5 | 전체 PoC 평가 및 제품화 판정 | 필수 8개 및 확장 기능 전체 | 확정 9개 작업 |

# 6. PoC 판정 체계

PoC 결과는 실행 상태, 기술 판정, 제품화 판정으로 구분해 기록한다.

## 6.1 실행 상태

| 상태 | 의미 |
|---|---|
| 완료 | 계획한 검증 실행 완료 |
| 보완 | 일부 기준 미충족으로 추가 작업 필요 |
| 실패 | 검증 목표 달성 실패 |
| 보류 | 데이터·권한·선행 조건 부족으로 실행 연기 |

## 6.2 기술 판정

| 판정 | 의미 |
|---|---|
| 기술 검증 완료 | 정의한 기술적 목표와 기준 충족 |
| 추가 검증 필요 | 가능성은 확인했으나 증빙 또는 품질 부족 |
| 외부 제약 | API·권한·정책·데이터 등의 제약 확인 |
| 검증 실패 | 기술적 목표 달성 실패 |

## 6.3 제품화 판정

| W5 판정 | 제품화 상태 | 의미 |
|---|---|---|
| Go | MVP 제품화 | 검증 통과, 제품화 개발 진행 |
| Conditional Go | 조건부 제품화 | 보완 조건과 일정 보호 조건 충족 시 진행 |
| No-Go | 재검증·제외 | 이번 MVP에서 구현하지 않음 |
| Hold | 제품화 보류 | 외부 권한·데이터·법적 검토 등 선행 조건 부족 |

기술 검증 완료가 곧바로 MVP 제품화 승인을 의미하지 않는다. 제품화 여부는 기술 결과, 품질, 개발 난이도, 외부 의존성과 잔여 일정을 종합해 W5에서 결정한다.

# 9. 최종 운영 원칙

1. WBS v1.2를 전체 일정과 작업 배분의 기준 문서로 사용한다.
2. 본 문서는 PoC 범위와 검증 기준을 정리하는 보조 문서로 사용한다.
3. 필수·확장 Agent 구분과 주차별 P0·P1·P2 작업 우선순위를 별도로 관리한다.
4. WBS에 확정된 작업과 조건부 작업을 혼합하지 않는다.
5. 조건부 작업은 필수 작업 완료와 공수 확보를 전제로 착수한다.
6. 확장 기능은 필수 MVP 일정과 품질을 우선 보호한다.
7. PoC 실행 결과는 실제 증빙을 확보한 후 기록한다.
8. 실제 데이터와 Mock 데이터의 사용 범위를 명확히 구분한다.
9. 외부 연동이 불가능한 경우 정책을 우회하지 않고 수동 입력·파일 생성·Mock 방식으로 대체한다.
10. 법규·인증·안전성은 AI가 최종 승인하지 않고 사람이 검토한다.
11. W5에서 제품화 여부를 결정하고 승인된 기능만 W6 이후 개발한다.
12. P1·P2 미수행 작업은 자동으로 제품화 일정에 이월하지 않는다.
13. 모든 제품화 결정에는 근거, 증빙, 담당자 및 후속 조건을 남긴다.
