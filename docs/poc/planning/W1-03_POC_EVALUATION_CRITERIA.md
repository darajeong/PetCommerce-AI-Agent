# PetCommerce AI Agent — PoC 평가 기준

> v0.4 · 2026.11.02 · 평가 기준 초안

## 1. 평가 목적과 전제

**본격적인 개발에 착수하기 전, 프로젝트의 핵심 가정을 검증한다.** 일반 프로그램과 AI를 각각 검증하고, 두 영역이 연동되었을 때 목표 업무가 실제로 원활히 수행되는지 확인한다.

본 문서는 각 PoC의 **실행 방법, 검증 수량, 허용 오류, 필수 증빙, 기준 미달 시 조치 사항**을 정의한다.

실험 시작 전 다음 사항을 확정해야 하며, 실험 실패 후 이 기준을 임의로 변경하는 것은 곧 **목표 변경**으로 기록한다.

- 목표 사용자·업무 및 대상 플랫폼·상품 유형
- 데이터 자동 수집 필수 여부 (수동 입력 허용 범위)
- 적합성 판정 필수 여부 (단순 판단 자료 제공으로 충분한지 여부)
- 상세페이지 초안 작성 범위 (초안 수준 vs 실제 판매 채널 등록까지)
- 마케팅 기획·홍보 이미지·영상 중 필수 산출물 및 목표 채널 (영상은 대본까지인지 완성 파일까지인지 정의)
- 상품당 허용 비용, 검수 소요 시간, 수동 개입량 및 기대 작업 시간 절감 목표

## 2. 업무별 적용 모델과 비교 방식
여기서 **모델**은 특정 회사의 제품이 아니라, 문제를 해결하는 방식(규칙, 통계, 분류, 추천, 생성 모델 및 이들의 조합)을 뜻한다. 제품은 구현 단계에서 선택하며, PoC 단계에서는 단순한 기준 방식과 비교하여 어떤 접근이 필요한지 판단한다.

| 업무               | 기존 기준 방식 (비교 대상)          | PoC 검증 모델 및 접근 방식                                     |
| ---------------- | ------------------------- | ----------------------------------------------------- |
| 상품 검색            | 키워드 사전·카테고리·조건 필터         | 언어 모델의 번역·질의 확장. 후보 집합 내 임베딩 유사도 검색 및 재정렬 비교          |
| 수집·번역·정규화        | API·파서·필드 매핑·단위 변환        | 정보 추출 및 기계번역 모델. 비정형 텍스트의 공통 필드 변환 및 원문 보존 여부 검증      |
| 상품 이미지 분석        | 상품 규격표·담당자 이미지 검토         | OCR·객체/속성 인식·시각 언어 모델. 시각적 특징과 문서 사양의 정합성 검증          |
| 리뷰 분석            | 키워드 규칙·빈도 집계              | 측면별 감성·불만 분류, 유사 불만 군집화, 근거 기반 요약 (집계는 코드로 수행)        |
| 적합성·스코어링         | 사람이 확인한 값·판단에 규칙 기반 점수 적용 | AI는 원문 근거 및 명시된 값 추출만 지원                              |
| 상품명·상세페이지·광고·SNS | 승인 문구·고정 템플릿              | 상품 근거 기반 조건부 텍스트 생성 (필요 자료 분산 시 RAG 비교)               |
| 마케팅 기획           | 사람이 정의한 고객군·메시지·채널 가설     | 언어 모델 기반 캠페인 가설 작성 (고객·성과 데이터 존재 시 세분화·반응 예측 모델 검증)   |
| 배너·홍보 이미지        | 원본 상품 사진 + 레이아웃 템플릿       | 이미지 조건부 생성 및 부분 편집 모델 (상품 형태 보존 배경·홍보 소재 제작)          |
| 영상 대본·장면 구성      | 정형 대본·장면 템플릿              | 언어 모델 기반 대본·스토리보드 생성 (상품 근거 및 영상 길이 조건 부여)            |
| 영상 소재 생성         | 원본 사진·클립의 프로그램 합성         | 이미지-to-영상 또는 텍스트-to-영상 모델 (상품 일관성 및 장면 연결 검증)         |
| 영상 내레이션          | 사람 녹음                     | 음성 합성(TTS) 모델 (발음, 속도, 대본 일치, 자막 동기화 검증)              |
| 확장 공급업체·경쟁·품질    | 근거표·비교 규칙·가중 순위           | 정보 추출·근거 기반 설명 및 콘텐츠 기반 추천 (구매 이력 확보 시에만 행동 기반 추천 검토) |
| 확장 성과 분석·고객 관리   | 지표 계산·규칙 기반 고객 구분         | 데이터 확보 시 군집화·예측·이상 탐지 모델, 결과 해석 및 메시지 생성 모델           |
| 채널 등록·원가 계산·실행   | API 매핑·계산식·상태 전이·승인 규칙    | AI 도입 없이 일반 프로그램으로 검증                                 |

스코어링을 제외한 모든 업무에서 지도학습이나 예측 모델을 검토하려면 정답·성과 데이터와 별도의 평가 자료가 필요하다. 데이터가 없다면 적용 가능성을 '미검증'으로 남기고, 생성형 AI의 설명으로 이를 대체하지 않는다. 모든 업무에 AI를 도입할 필요는 없으며, **규칙만 적용 / AI만 적용 / 양자 결합** 중 허용된 방식을 같은 조건으로 비교한다. 스코어링은 사람이 확인한 입력값을 바탕으로 규칙 계산만 수행한다.

- **일반 프로그램 PoC:** 실제 계정·데이터·외부 연동 환경에서 불확실한 요소를 소스 스크립트로 검증한다. 합계 계산 및 일반 CRUD는 개발 테스트로 확인한다.
- **AI PoC:** 실제 데이터와 정답안(Ground Truth)을 바탕으로 정확도, 판단 한계, 검수량을 확인한다.
- **결합 PoC:** AI 출력을 코드가 정상적으로 처리할 수 있는지, 검수 과정을 포함하여 실제 업무 효율이 개선되는지 확인한다.

## 3. 핵심 PoC 평가 기준

| 검증 항목   | 검증 질문 및 유형                                      | 최소 실험 및 통과 근거                                                      | 실패 시 영향               |
| ------- | ----------------------------------------------- | ------------------------------------------------------------------ | --------------------- |
| 데이터 접근  | 목표 상품과 필요한 자료를 수집할 수 있는가? (**프로그램·AI**)         | 검색 경로·키워드 후보 비교 및 실제 데이터 수집. Rate Limit·차단·재개 조건 내 목표 처리량 달성 여부 확인 | 데이터 소스 및 자동화 방식 변경    |
| 판단 근거   | 확보한 자료로 적합성을 판정할 수 있는가? (**사람 선행 검토**)          | 담당자가 유형별 규격·하중·사용 조건을 사전 검토. 판단 기준 및 정답안 작성                        | 평가 기능 및 대상 상품 변경      |
| AI 해석   | 번역·특징·불만·판단 근거를 정확히 추출하는가? (**AI**)             | 실제 데이터로 반복 실행 후 사람 답안과 비교. 핵심 수치/불만 오류 및 근거 없는 주장 0건 달성            | 자동 분석 범위 및 검수량 변경     |
| 콘텐츠 활용  | 상세페이지·마케팅·영상 산출물을 실제 업무에 쓸 수 있는가? (**프로그램·AI**) | 산출물에 대한 사람의 검수·수정 및 템플릿 방식과의 비교. 사실·규격 검수 및 수정 시간·비용 충족            | 콘텐츠 제작 범위 및 업무 가치 재검토 |
| 프로그램 연결 | AI 결과물을 후속 프로세스로 연계할 수 있는가? (**결합**)            | 입력 → AI → 형식 검사·규칙 계산 → 초안·승인 대기 연동 확인. 예외 응답 및 승인 거절 시나리오 테스트     | 출력 계약 및 실행 구조 변경      |
| 업무 효과   | 검수 과정을 포함하여 시간·비용 목표를 달성하는가? (**결합**)           | 수작업·템플릿·AI 결합 방식을 동일 상품으로 비교. 품질 유지하며 사전 정의된 시간·비용·개입 기준 충족        | 처리량·비용·핵심 가치 재조정      |

데이터 접근과 판단 근거를 우선 확인한 뒤 AI 해석을 검증한다. 콘텐츠 생성은 입력이 준비되는 대로 병행하고, 입출력 구조가 갖춰지면 프로그램 연동 및 업무 효과를 검증한다(W5 종합 완료).

### 1) 데이터 접근 검증

- **착수 전 확인:** 수집 전 플랫폼 약관, 자동 접근 허용 범위, 계정 권한 확인 후 공식 URL 및 확인일 기록. 리뷰 개인정보 비식별화, 이미지 저장 및 홍보 재사용 권한 확인 필수.
- **검색 방법:** 공식 검색 API, 허용된 웹 검색, 카테고리 탐색 중 가용한 경로를 실제 계정으로 실행하여 접근 범위 기록.
- **키워드 생성:** 검색 조건 고정 후, 사람이 만든 검색어와 AI 번역·동의어 후보를 동일 경로에서 비교. (비용, 중복률, 적합 상품 비율 측정)
- **Rate Limit:** 공식 문서의 호출량·동시성 한계와 실제 응답 대조. 429 및 Retry-After 발생 시 대기·재시도 로직 검증.
- **차단·중단 조건:** 403, CAPTCHA, 로그인 만료 등을 구분하고 자동 재시도 중단 및 사람 확인 후 재개 프로세스 점검.

### 2) 스코어링(점수 산정) 검증

- **지도학습·분류 모델 배제:** AI는 원문에 명시된 근거와 값만 추출하며, 스코어링은 사람이 확인한 입력값에 규칙(Rule)을 적용해 산출한다.

1. **채점표 정의:** 항목별 필수 근거, 계산식, 배점, 등급 경계를 고정한다 (정성적 항목은 보류 가능).
2. **AI의 근거 추출:** 출력은 `항목 / 원문 값·단위 / 출처 인용문`으로 제한한다 (AI의 주관적 점수 생성 금지).
3. **사람 확인 후 코드 계산:** 추출된 값을 사람이 검수·승인한 뒤 계산식에 대입한다.
4. **검증:** 2명의 검토자가 독립적으로 작성한 기준 답안과 대조하여 불일치율과 추출 오류를 측정한다.

### 3) 마케팅·영상·홍보자료 검증

- 상품 정보, 원본 이미지, 고객군, 메시지를 공통 입력으로 하여 대표 사례 1건씩 제작 가능성을 검증한다.
- **마케팅 기획:** 실제 실행 가능한 캠페인 구체화 여부 및 허위 시장 데이터 제시 여부 검증.
- **광고 문안·SNS:** 채널별 규격 및 필수 문구 준수 여부, 허용 수정 시간 내 활용 가능성 검증.
- **배너·홍보 이미지:** 원본 형태·색상·로고 왜곡 여부 및 가독성 검증.
- **영상:** 대본부터 장면, 음성, 자막, 최종 파일까지의 파이프라인 검증 (대본 생성만으로는 영상 제작 완료로 인정하지 않음).

### 4) 기존 W1-02 평가 기준 유지 항목

- **검색·수집(A01·A02):** 플랫폼별 검색어 1개 이상, 후보 URL 5개 이상 및 선정 3개 확보. 3개 상품 연속 처리 시 1개의 실패가 전체 프로세스를 중단시키지 않아야 함.
- **번역·정규화(A03):** 의미 보존율 90% 이상, 상표명 임의 번역 및 핵심 수치 오류 0건, 원문 연결률 100%.
- **기록·재현:** 상품·실행·Agent ID, 원본 URL, 수집 시각, 가격·옵션·규격, 결과 버전 및 오류 이력을 100% 보존하며 타 팀원이 재현 가능해야 함.

## 4. 실험 방법과 완료 기준

### 기준 동결 및 자료 관리

- **동결:** C가 취합하고 D가 검토하여, 첫 평가 실행 전 모든 정확도·허용 오류·표본 기준을 `기준-v1`로 고정한다.
- **자료 분리:** 개발/파일럿용 데이터와 평가용 데이터 ID 목록을 사전에 엄격히 분리한다.
- **실행 고정:** 원본, 정답안, 프롬프트, 모델 버전, 디코딩 설정 등을 기록하여 재현성을 확보한다.

### 최소 표본 및 수치 제안 (초기 기준)

| 평가 대상      | 최소 표본 수량 제안                    | 통과 기준 제안                       |
| ---------- | ------------------------------ | ------------------------------ |
| 검색         | 플랫폼별 검색 조건 3개, 상위 10개 결과       | 적합 상품 비율 80% 이상                |
| 추출·번역·정규화  | 실제 상품 3개 이상, 핵심 필드 30개 이상      | 핵심 수치·옵션 오류 0건, 전체 정확도 95% 이상  |
| 리뷰·특징 분류   | 실제 리뷰 60개 이상, 이미지·설명 주장 30개 이상 | 분류 정확도 90% 이상, 핵심 불만 누락 0건     |
| 적합성        | 실제 상품 3개 이상, 판정 항목 30개 이상      | 사람 답안 일치율 90% 이상, 부적합 오판 0건    |
| 콘텐츠·이미지·영상 | 서로 다른 입력 3건                    | 사실·규격 검수 통과 및 수정 시간·비용 상한 이내   |
| 최소 연결 연동   | 실제 상품 3개 × 동일 입력 3회 (총 9회)     | 예외 상황 포함 9회 모두 정상 출력 도달, 유실 0건 |

- **업무 효과:** 수작업 대비 **총 소요 시간 50% 이상 절감**을 기본 목표로 하되, 파일럿 이후 최종 확정한다.

## 5. 평가 결과와 제품화 판단

실험 결과는 `완료 / 보완 / 실패 / 보류`로 판정하며, 핵심 가정 중 하나라도 미통과 시 본개발 진입을 보류한다.

| 판정                 | 적용 조건                                |
| ------------------ | ------------------------------------ |
| **Go**             | 핵심 가정 통과. 증빙 및 개발 완료 기준을 확보하여 본개발 착수 |
| **Conditional Go** | 핵심 가정 통과 및 비핵심 보완에 대한 담당자·기한 명확화     |
| **Hold**           | 데이터·권한·판정 기준 부족으로 검증 유예              |
| **No-Go**          | 검증 실패 및 해결 경로 부재 시 프로젝트 중단 또는 피벗     |

- **핵심 가정이 실패하거나 미검증 상태일 경우,** 이에 의존하는 본개발은 홀드(Hold)한다. 단순 원인 기록만으로 통과 처리하지 않는다.

## 6. 후속 개발로 넘길 것

완성 UI, 일반 CRUD, 전체 권한 및 장애 조합 검사, 부하·배포·운영 안정성은 MVP 개발 및 인수 단계에서 검증한다. PoC 통과는 어디까지나 **본개발 착수 자격**을 의미하며, 상품 3개 테스트 결과로 운영 전반의 안정성이나 매출 효과를 최종 입증한 것으로 간주하지 않는다.
