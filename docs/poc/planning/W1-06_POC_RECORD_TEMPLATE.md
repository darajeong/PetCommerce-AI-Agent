## 1. 목적과 적용 범위

본 문서는 W2-W5의 모든 PoC가 **같은 항목, 같은 값 체계, 같은 순서**로 실행 과정과 결과를 기록하도록 양식을 정의한다. 기록은 다음 두 층으로 구성한다.

| 구분 | 단위 | 역할 |
|---|---|---|
| PoC 실행 기록 (§5) | PoC ID 1건당 1개 | 목표·준비·절차·회차별 실행·결과·오류·판정·다음 작업의 원본 기록 |
| PoC 결과 비교표 (§6) | 전체 PoC 1개 | 각 기록의 요약 블록(§5-0)을 한 행으로 모아 PoC 간 결과를 비교 |

- **적용 대상:**
  - WBS의 PoC 작업 전체(A01-01 ~ E04-02, B-INT-01, DE-INT-01 등)
  - W1-08 샘플 PoC
  - W5 실행형 작업: W5-01 필수 흐름 1차, W5-02 3개 상품 반복, W5-04 오류와 대체 경로, W5-06 성능·비용. 이 중 통합 실행은 §5-5의 단계별 행 규칙을 따른다.
- **적용 제외:** W5-03 품질 평가, W5-05 권한·법규·보안 검토, W5-07 ~ W5-09 판정·확정 작업은 각자의 산출물 양식을 사용한다. 다만 본 양식으로 작성한 기록을 입력으로 쓴다.
- **문서 적용 순서:** WBS v1.2 > 본 문서 > W1-02 §8 순으로 적용한다. 본 문서는 WBS 「PoC 기록 양식」과 W1-02 §8을 모두 포함해 상세화한 것이다.
- **다른 문서와의 역할 구분:** 본 문서는 아래 내용을 새로 정하지 않고, 해당 문서의 값을 옮겨 적는다.
  - 판정 기준 수치, PoC별 검증 유형, 핵심 가정: W1-03
  - 데이터 ID와 필드: W1-04
  - 분석·점수 기준: W1-05
- **기록 단위:** PoC ID 1건에 기록 1개를 작성한다. 반복 실행은 같은 기록 안의 회차로 추가한다. 재실행 결과는 기존 회차를 덮어쓰지 않고, 새 회차와 새 결과 버전으로 남긴다.

| 시점 | 작성 범위 | 작성자 | 통과 조건 |
|---|---|---|---|
| ① 착수 전 | §5-1 기본 정보, §5-2 검증 정의, §5-3 준비 사항 | 주 담당 | 판정 기준과 기준 버전을 기록하고 첫 실행 전에 고정 |
| ② 실행 중 | §5-4 실행 절차, §5-5 회차별 실행 로그, §5-7 오류 기록 | 주 담당 | 회차마다 실행 ID·상품 ID·평가 단위 ID·증빙 링크 기록 |
| ③ 실행 후 | §5-6 결과, §5-8 재현 확인, §5-9 판정, §5-10 다음 작업, §5-0 요약 | 주 담당 (재현은 다른 팀원) | 모든 기준에 측정값·판정·증빙 연결 |
| ④ 검토 | §5-11 검토 기록 | 검토 담당 | §7 체크리스트 전 항목을 확인한 뒤 승인 또는 보완 요청 |
| ⑤ 비교표 반영 | §6 결과 비교표 1행 | 주 담당 | §5-0 요약과 값 일치 |

- **기준 변경:** 첫 실행 이후 판정 기준·목표값·표본 수를 바꾸면 W1-03 원칙에 따라 **목표 변경**으로 §5-12 변경 이력에 기록하고, 검토 담당의 확인을 다시 받는다.

### 2.1 기준 버전과 적용 시점

판정은 항상 **그 회차를 실행할 때 기록해 둔 기준 버전**으로 한다. 나중에 정해진 기준으로 과거 회차를 다시 판정해 통과 처리하지 않는다.

| 상황 | 기록 방법 |
|---|---|
| W1-03 `기준-v1` 동결 전 실행 (W2 초 등) | §5-2 기준 버전 칸에 실제로 사용한 버전을 적는다(예: `W1-03 v0.5 초안`). 이 버전으로 판정하고, 판정 근거에 `기준-v1 동결 전 실행`이라고 적는다. |
| `기준-v1` 동결 후 | 동결 이후에 시작하는 회차부터 `기준-v1`을 적용한다. 이미 끝난 회차의 기준 버전과 판정은 바꾸지 않는다. |
| 동결 전 기록을 `기준-v1`로 판정하려는 경우 | 기준 항목별로 초안과 `기준-v1`을 대조해 §5-12에 기록한다. ① 목표값·표본 수·허용 오류·필수 증빙이 모두 같은 기준만 검토 담당의 확인을 받아 기존 결과를 그대로 쓴다. ② 하나라도 다르거나 새로 생긴 기준은 동결 후 **새 회차로 재검증**한다. 재검증 전에는 해당 기준을 `측정 불가(기준-v1 미검증)`로 둔다. |
| W1-06 확정 전에 작성된 기록 | W1-08 §6.4 샘플 기록과 W2-A01-01 기록은 W1-06 확정 전 임시 양식으로 작성되었다. 본 양식으로 옮기더라도 당시 판정을 그대로 옮기고(기준 버전 `W1-03 미동결`), 위 대조·재검증을 거치기 전에는 실행 상태 `완료`나 기술 판정 `기술 검증 완료`로 바꾸지 않는다. W1-08 샘플은 환경 스모크 테스트이므로 W1-03 판정 대상이 아니다(W1-08 §6.4). |

- 동결된 `기준-v1`을 다시 바꾸는 경우의 사유·승인·버전 규칙은 W1-03 §4를 따른다. 기준이 바뀌어도 이전 버전으로 판정한 결과를 새 버전으로 통과 처리하지 않는다.
- **증빙 없는 완료 금지:** 실제 실행 증빙이 없는 PoC는 `완료`로 기록하지 않는다(W1-02 원칙 8).
- **미착수 작업 (W1-02 §3.2 "실패가 아니라 미착수·보류로 기록"):** 착수하지 못한 조건부 작업은 다음과 같이 기록한다.
  - 실행 상태는 `보류`로 적고, 사유를 `미착수(착수 조건 미충족)`로 적는다.
  - §5-0, §5-1, §5-2, §5-9, §5-10만 작성한다.
  - 나머지 절은 절 제목 아래에 `해당 없음(미착수)`라고 한 줄만 적는다.

  | Conditional Go | 조건부 제품화 |
  | No-Go | 재검증·제외 |
  | Hold (실행 상태 `완료`) | PoC 완료·제품화 보류 |
  | Hold (실행 상태 `보완`·`실패`·`보류`, 미착수 포함) | 제품화 보류(PoC 미완료) |

  WBS의 `PoC 완료·제품화 보류`는 "PoC를 끝냈지만 선행 조건이 부족해 제품화를 미룬다"는 뜻이다. 따라서 PoC를 끝내지 못한 Hold에 이 값을 쓰면 실행 상태 `완료`와 충돌한다. 이 경우는 `제품화 보류(PoC 미완료)`로 적는다. 이 값은 W1-06에서 추가했으며, W5-08 담당(A)이 확인하고 W5-08 판정 체계 표에도 같은 이름으로 쓰기로 했다(2026-11-05, PR #8).

- **`해당 없음`을 쓰는 경우:** 필수 보조 작업(B-INT-01, DE-INT-01 등)과 W5 실행형 작업은 Agent가 아니므로 제품화 제안·W5 최종 판정·제품화 상태를 `해당 없음`으로 적는다.
- **Agent 단위 종합:** 한 Agent에 PoC가 여러 개이면 PoC마다 제안을 적는다. 이를 Agent 단위로 종합하는 것은 W5-08에서 한다.
- **미착수 PoC의 기술 판정 (W1-06 추가):** W5-07 이전에 착수하지 못한 PoC는 기술 판정 칸에 `미판정(미착수)`을 임시로 쓸 수 있다.
  - W5-07에서 다음 중 하나로 확정한다. 권한·정책·데이터 제약 때문이면 `외부 제약`, 그 밖의 사유이면 `추가 검증 필요`.
  - 착수하지 않은 PoC는 `검증 실패`로 판정하지 않는다(W1-02 §3.2).
  - W5-07 완료 기준은 미판정 PoC 0건이다.

### 3.3 판정 간 일관성 규칙

| 규칙 | 내용 |
|---|---|
| R1 | 실행 상태 `완료`는 두 조건을 모두 충족할 때만 쓴다. ① 계획한 회차마다 최종 회차(§5-5 재실행 규칙)가 있다. ② 모든 기준에 기준 판정과 증빙이 기록되었다. |
| R2 | 기술 판정 `기술 검증 완료`는 세 조건을 모두 충족할 때만 쓴다. ① 실행 상태가 `완료`다. ② 필수 기준이 모두 `충족`이다(R10 조건을 모두 갖춘 `해당 없음`만 제외). ③ §5-8 재현 결과가 `기준 판정 동일`이다. |
| R3 | 필수 기준 중 `미충족` 또는 `측정 불가`가 있으면 실행 상태는 `보완`·`실패`·`보류` 중 하나로 적고, 사유를 §5-9에 적는다. 원인을 기록한 것만으로 `완료` 처리하지 않는다. |
| R4 | 실행 상태가 `보류`이면 `기술 검증 완료`를 쓰지 않는다. 권한·정책·데이터 제약이 확인되면 `외부 제약`을, 가능성은 확인했지만 증빙이 부족하면 `추가 검증 필요`를 쓴다. 미착수 건은 §3.2 규칙을 따른다. |
| R5 | 제품화 제안 `Go`는 기술 판정이 `기술 검증 완료`일 때만 할 수 있다. 단, 기술 검증 완료가 곧 제품화 승인을 의미하지는 않는다(W1-02 §6.3). |
| R6 | `Conditional Go`와 `Hold`를 제안하면 §5-10에 보완 조건 또는 선행 조건, 담당자, 기한, 재판정 시점을 기록한다. |
| R7 | `No-Go`를 제안하면 §5-10에 제외 사유와 재검증 조건을 기록한다(WBS W5 판정 체계). |
| R8 | 회차 결과보다 기준 판정이 우선한다. 예: 3회 모두 `성공`이어도 근거 연결률이 100% 미만이면 해당 기준은 `미충족`이다. |
| R9 | 핵심 가정 여부가 `예`인데 기술 판정이 `기술 검증 완료`가 아니면, 제품화 제안은 `Hold` 또는 `No-Go`만 쓸 수 있다(W1-03 §5: 핵심 가정이 실패하거나 미검증이면 의존 본개발 Hold). |
| R10 | 필수 기준의 `해당 없음`은 **기준이 이 PoC에 본질적으로 적용되지 않을 때만** 쓴다. 다음 세 조건을 모두 갖춰야 하며, 하나라도 빠지면 `측정 불가`로 본다. ① 적용 제외 사유가 기준 문구 자체에서 나온다(예: A01-01 "접근 가능 플랫폼은 후보 URL 5개 이상"에서 접근 불가로 확인된 플랫폼. 이때 대신 적용되는 "인증·차단 오류 증빙과 대체 방법" 기준은 필수로 판정한다). ② 첫 실행 전 §5-2에 적용 제외로 표시했다. 실행 중 알게 된 경우는 §5-12에 기록한다. ③ 검토 담당이 승인하고 §5-6 근거 칸에 `승인: <검토 담당>, <일자>`를 남겼다. 이 조건을 갖춘 기준만 `필수 기준 충족` 집계의 분모에서 뺀다. |
| R11 | 자료·계정·권한을 확보하지 못했거나, 측정을 하지 못했거나, 측정 결과가 목표에 못 미친 필수 기준은 `해당 없음`으로 적지 않는다. 각각 `측정 불가(사유)` 또는 `미충족`으로 적고, R3에 따라 실행 상태를 `보완`·`실패`·`보류`로 둔다. 이런 기준이 하나라도 있으면 `기술 검증 완료`를 쓸 수 없다. (W1-06 추가) |
| R12 | W5-08 확정 전에는 W5 최종 판정과 제품화 상태를 `W5 판정 전`으로 둔다. W5 최종 판정이 `Hold`이면 제품화 상태는 실행 상태에 따라 §3.2 대응표대로 적는다. (W1-06 추가) |

### 3.5 표기 규칙

- **빈칸 금지:** 칸을 비워 두지 않는다. 값이 없으면 다음 중 하나를 적는다.
  - `없음`: 해당 사항이 0건일 때
  - `해당 없음`: 이 PoC에 적용되지 않을 때
  - `측정 불가(사유)`
  - `누락(누락 사유)`
- **시각:** 기록 문서에는 KST, `YYYY-MM-DD HH:mm` 형식으로 적는다. W1-04 JSON은 ISO 8601(`2026-11-02T10:00:00+09:00`)로 저장하므로, 문서 값은 JSON 값의 날짜·시·분을 그대로 옮긴 표시용 값이다. 초 단위가 필요하거나 JSON과 대조할 때는 JSON 값을 원본으로 본다.
- **처리 시간:** 초(s) 단위로 적는다. 사람의 수동 작업 시간은 분(min) 단위로 따로 적는다.
- **AI 비용:**
  - §5-5에는 청구 통화 그대로 통화 코드와 함께 적는다(예: `0.042 USD`).
  - §5-0과 §6.2에는 비교를 위해 원화(KRW)로 환산한 값을 적고, 환율과 기준일을 비고에 적는다.
- **비율:** `분자/분모 (백분율)` 형식으로 적는다(예: `29/30 (96.7%)`).
- **상한 비교:**
  - WBS의 처리 시간·AI 비용·실패율·수동 개입 상한은 **상품 1건 전체 흐름**과 **통합 실행**을 기준으로 한다.
  - 따라서 상한 비교는 통합 실행 기록(W5-01·W5-02·W5-06)에만 적는다. 상한이 정해지기 전에는 `상한 미정`, 정해진 뒤에는 `이내` 또는 `초과`로 적는다.
  - 그 밖의 PoC는 수치를 참고값으로만 기록하고, 상한 비교 칸에는 `해당 없음`을 적는다.
- **ID:** 실행 ID·상품 ID·결과 버전의 형식은 W1-04 공통 데이터 구조를 따른다. W1-04 v0.1 기준으로 `run_id`·`product_id`·`agent_id`는 문자열(예: `run-demo-002`, `prod-demo-002`, `A02`)이고, `input_version`·`result_version`은 정수다. 승인 대상은 `agent_id:result_version` 형식으로 적는다(예: `A02:1`).
- **증빙 링크:** 저장소 상대 경로 또는 만료되지 않는 URL로 적는다. 개인 메신저 링크와 로컬 경로는 증빙으로 인정하지 않는다.
- **보안·권리:**
  - API Key·비밀번호·세션 토큰은 기록하지 않는다.
  - 리뷰의 개인정보는 비식별화한다.
  - 이미지·리뷰·설명 원문의 저장·AI 입력·표시·재사용은 W1-04 `usage` 4개 용도(`usage.store`·`usage.ai_input`·`usage.display`·`usage.resale`)를 각각 따른다. 각 행위는 해당 용도가 `allowed`일 때만 한다. 확인 전 기본값은 네 용도 모두 `needs_review`다(W1-04, W1-07 1.1절).
  - 용도가 `allowed`가 아닌 자료는 저장·외부 AI 입력·표시하지 않는다. 기록과 저장소에는 URL·ID(`image_id`·`review_id`)·용도별 권한 상태만 적는다. PoC 내부 검증 상품도 예외가 아니며, 저장소 밖 비공개 위치에 보관하는 것도 저장에 해당한다.
  - 권한이 확인되지 않은 원문이 필요한 단계는 권한이 확인된 자료나 완전 합성 테스트 데이터(`data_type: test`)로 대체하고, §5-3 데이터 구분에 `테스트`(항목별로 다르면 `혼합`)로 적는다.
  - 외부 AI API의 학습 미사용 설정은 보안 조치로 기록하며, 콘텐츠 이용 권한을 대신하지 않는다.

### 3.6 W1-04 코드 대응표

### 5-5. 회차별 실행 로그

**작성 규칙**

- **회차:** 평가 단위 1개를 1회 실행한 것을 회차 1개로 센다. 반복 실행은 `반복` 번호로 구분한다.
- **재실행:** 새 회차로 추가하고, `재실행 대상` 열에 대체하는 원 회차 번호를 적는다.
  - 원 회차의 행은 지우지 않는다.
  - 판정과 변동 폭 계산(예: B-INT-01 3회 비교)에는 각 반복의 **최종 회차**를 쓴다.
- **통합 실행 (W5-01·W5-02 등):** 한 회차 안에서 Agent 단계마다 1행씩 기록하고, 마지막 행의 `Agent·단계`에 `전체`를 적는다.
  - 두 표는 `회차 + Agent·단계`를 키로 연결한다.
- **다른 기록의 실행 재사용:** W5-06처럼 다른 기록의 실행을 다시 쓰면, `증빙` 열에 원 기록 링크와 원 실행 ID를 적는다.
- **집계 (§5-0 회차 결과·실패율):**
  - 단일 PoC는 회차 단위로 센다.
  - 통합 실행은 `전체` 행만 센다.
  - 실패율은 재실행을 포함한 전체 회차를 분모로 한다.

## 6. PoC 결과 비교표

모든 PoC 기록의 §5-0 요약을 모은 표다. 한 화면에서 비교할 수 있도록 **판정 뷰**와 **수치 뷰** 두 표로 나누고, 두 표는 PoC ID로 연결한다.

- **갱신 시점:** W2-W4 동안 매주 금요일 시연 전에 갱신한다.
- **용도:** W5-07 PoC 의사결정표의 입력으로 사용한다.
- **값이 다를 때:** 비교표와 PoC 기록의 값이 다르면 PoC 기록을 기준으로 바로잡는다.

### 6.1 판정 뷰

| PoC ID | Agent | 범위 | 주 / 검토 | 핵심 가정 | 기준 버전 | 실제·Mock 범위 | 필수 기준 충족 | 실행 상태 | 기술 판정 | 판정 근거 | 제품화 제안 (주 담당) | W5 최종 판정 / 제품화 상태 | 핵심 제한 사항·미검증 범위 | 다음 작업 | 검토 결과 | 기록 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| `<A02-01>` | `<A02>` | `<필수>` | `<B / C>` | | `<W1-03 v0.5 초안>` | | `<n/m · 측정 불가 n>` | | | | `<제안값>` | `W5 판정 전` | | | | `<링크>` |

### 6.2 수치 뷰

| PoC ID | 평가 단위 | 수량 (계획 / 실제) | 회차 결과 (성공·부분·실패·보류) | 실패율 | 근거 연결률 | 원본에 없는 주장 | 평균 처리 시간(s) | 평균 AI 호출 / 토큰 | 평균 AI 비용 (KRW) | 평균 수동 개입 | 상한 초과 항목 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `<A02-01>` | `<상품>` | | `<n·n·n·n>` | | | | | | | | `<없음·상한 미정·해당 없음·항목명>` |

- **정렬:** Agent 그룹(A→E) 순으로 정렬하고, 같은 그룹 안에서는 PoC ID 순으로 정렬한다.
- **비교 방법:**
  - 같은 Agent 안에서는 필수 기준 충족 수와 기술 판정을 비교한다.
  - 처리 시간·AI 비용·실패율·수동 개입은 `평가 단위`가 같은 PoC끼리만 비교한다.
  - 상한과의 비교는 통합 실행 기록에만 적용한다(§3.5).
- **승인 전 행:** `검토 결과`가 `승인`이 아닌 행은 W5-07 판정 입력으로 쓰기 전에 검토를 마친다.
- **기준 버전이 다른 행:** `기준 버전`이 다른 PoC끼리는 필수 기준 충족 수를 그대로 비교하지 않는다. `기준-v1` 동결 전 버전으로 판정한 행은 §2.1 대조·재검증 전까지 W5-07에서 `기준-v1 미적용`으로 표시한다.
- **제안과 확정의 구분:** `제품화 제안` 열은 주 담당의 의견이다. W5-08 전에는 `W5 최종 판정 / 제품화 상태` 열이 모두 `W5 판정 전`이어야 한다.
- **W5-07 연결:** W5-07 완료 기준의 각 항목은 판정 뷰의 다음 열에서 가져온다.

  | 증빙 링크 | `기록` |
  | 실제/Mock 여부 | `실제·Mock 범위` |
  | 제한 사항 | `핵심 제한 사항·미검증 범위` |

## 7. 검토 체크리스트

검토 담당은 아래 항목을 확인하고, 결과를 §5-11에 기록한다.

**기준과 기록**

1. 판정 기준과 실제로 사용한 기준 버전이 첫 실행 전에 기록되었고, 이후 변경은 §5-12에 `목표 변경`으로 남아 있다. 동결 전 버전으로 판정한 결과를 `기준-v1` 결과로 바꾼 경우 §2.1의 대조·재검증 기록이 있다.
2. WBS 완료 기준과 W1-03 기준이 모두 §5-2에 `필수` 기준 ID로 나뉘어 있다. 각 기준에 허용 오류·실패 시 처리·필수 증빙이 있고, §5-6에 같은 ID의 결과가 있다.
3. 모든 회차에 실행 ID·상품 ID(또는 `해당 없음` 사유)·평가 단위 ID·데이터 구분·결과 버전·증빙 링크가 있다.
4. 재실행 회차에는 재실행 대상이 적혀 있고, 원 회차가 지워지지 않았다.
5. 통합 실행이면 다음 세 가지가 모두 기록되어 있다.
   - Agent 단계마다 행이 있다.
   - 이전 단계의 결과 버전이 연결되어 있다.
   - 측정값 표가 단계별로 대응한다.

**데이터와 오류**

6. 실제·테스트·Mock 데이터 구분이 입력 데이터, 회차 로그, 판정의 실제·Mock 범위에서 서로 일치한다.
7. 필수 데이터 누락이 정해진 누락 사유로 기록되었다.
8. 실패·부분 성공 회차마다 §5-7에 실패 단계·원인·처리 결과·다음 행동이 있다.

**재현성**

9. 다음 항목이 재현할 수 있는 수준으로 기록되었다: 소스 커밋, 실행 명령, 지시문 버전, 모델 버전, 디코딩 설정, 정답안 버전.
10. 주 담당이 아닌 팀원이 재현을 확인했다.

**승인과 판정**

11. 외부 실행의 관리자 승인 상태가 기록되었고, 승인 없이 외부 단계가 실행된 사례가 없다.
12. 실행 상태·기술 판정·제품화 제안·W5 최종 판정·제품화 상태가 §3.3 일관성 규칙 R1 ~ R12를 위반하지 않는다. 특히 필수 기준의 `해당 없음`이 R10 세 조건(본질적 비적용, 사전 표시, 검토 담당 승인)을 갖추었고, 자료·권한 미확보나 실패가 `해당 없음`으로 처리되지 않았다(R11).
13. `Conditional Go`·`Hold`·`No-Go`에는 R6·R7이 요구하는 조건·사유·담당자·기한·재판정 시점이 있다.

**보안과 정합성**

14. 기록이나 저장소에 올린 증빙에 비밀 정보, 개인정보, `usage`가 `allowed`가 아닌 원본 파일이 포함되지 않았고, 그런 원본을 저장소 밖에 보관하지도 않았다. 권한 미확인 자료는 URL·ID·용도별 권한 상태로만 기록되었고, 대체 데이터는 데이터 구분에 `테스트`로 표시되었다.
15. §5-0 요약, §6 결과 비교표, 본문의 값이 서로 일치한다. JSON 결과를 옮긴 값은 §3.6 대응표와 맞는다.
