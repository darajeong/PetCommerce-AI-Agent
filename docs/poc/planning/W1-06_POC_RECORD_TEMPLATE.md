## 1. 목적과 적용 범위

본 문서는 W2-W5의 모든 PoC가 **같은 항목, 같은 값 체계, 같은 순서**로 실행 과정과 결과를 기록하도록 양식을 정의한다. 기록은 다음 두 층으로 구성한다.

| 구분 | 단위 | 역할 |
|---|---|---|
| PoC 실행 기록 (§5) | PoC ID 1건당 1개 | 목표·준비·절차·회차별 실행·결과·오류·판정·다음 작업의 원본 기록 |
| PoC 결과 비교표 (§6) | 전체 PoC 1개 | 각 기록의 요약 블록(§5-0)을 한 행으로 모아 PoC 간 결과를 비교 |

- **적용 대상:**
  - WBS의 PoC 작업 전체(A01-01 ~ E04-02, B-INT-01, DE-INT-01 등)
  - W1-08 샘플 PoC
  - W5 실행형 작업: W5-01 필수 흐름 1차, W5-02 3개 상품 반복, W5-04 오류와 대체 경로, W5-06 성능·비용. 이 중 통합 실행은 §5-5의 단계별 행 규칙을 따른다.
- **적용 제외:** W5-03 품질 평가, W5-05 권한·법규·보안 검토, W5-07 ~ W5-09 판정·확정 작업은 각자의 산출물 양식을 사용한다. 다만 본 양식으로 작성한 기록을 입력으로 쓴다.
- **문서 적용 순서:** WBS v1.2 > 본 문서 > W1-02 §8 순으로 적용한다. 본 문서는 WBS 「PoC 기록 양식」과 W1-02 §8을 모두 포함해 상세화한 것이다.
- **다른 문서와의 역할 구분:** 본 문서는 아래 내용을 새로 정하지 않고, 해당 문서의 값을 옮겨 적는다.
  - 판정 기준 수치, PoC별 검증 유형, 핵심 가정: W1-03
  - 데이터 ID와 필드: W1-04
  - 분석·점수 기준: W1-05
- **기록 단위:** PoC ID 1건에 기록 1개를 작성한다. 반복 실행은 같은 기록 안의 회차로 추가한다. 재실행 결과는 기존 회차를 덮어쓰지 않고, 새 회차와 새 결과 버전으로 남긴다.

## 2. 기록 작성 시점

| 시점 | 작성 범위 | 작성자 | 통과 조건 |
|---|---|---|---|
| ① 착수 전 | §5-1 기본 정보, §5-2 검증 정의, §5-3 준비 사항 | 주 담당 | 판정 기준과 기준 버전을 기록하고 첫 실행 전에 고정 |
| ② 실행 중 | §5-4 실행 절차, §5-5 회차별 실행 로그, §5-7 오류 기록 | 주 담당 | 회차마다 실행 ID·상품 ID·평가 단위 ID·증빙 링크 기록 |
| ③ 실행 후 | §5-6 결과, §5-8 재현 확인, §5-9 판정, §5-10 다음 작업, §5-0 요약 | 주 담당 (재현은 다른 팀원) | 모든 기준에 측정값·판정·증빙 연결 |
| ④ 검토 | §5-11 검토 기록 | 검토 담당 | §7 체크리스트 전 항목을 확인한 뒤 승인 또는 보완 요청 |
| ⑤ 비교표 반영 | §6 결과 비교표 1행 | 주 담당 | §5-0 요약과 값 일치 |

- **기준 변경:** 첫 실행 이후 판정 기준·목표값·표본 수를 바꾸면 W1-03 원칙에 따라 **목표 변경**으로 §5-12 변경 이력에 기록하고, 검토 담당의 확인을 다시 받는다.
- **증빙 없는 완료 금지:** 실제 실행 증빙이 없는 PoC는 `완료`로 기록하지 않는다(W1-02 원칙 8).
- **미착수 작업 (W1-02 §3.2 "실패가 아니라 미착수·보류로 기록"):** 착수하지 못한 조건부 작업은 다음과 같이 기록한다.
  - 실행 상태는 `보류`로 적고, 사유를 `미착수(착수 조건 미충족)`로 적는다.
  - §5-0, §5-1, §5-2, §5-9, §5-10만 작성한다.
  - 나머지 절은 절 제목 아래에 `해당 없음(미착수)`라고 한 줄만 적는다.

## 3. 공통 값 체계

비교할 수 있도록 아래 칸에는 **정해진 값만** 사용한다. 자유 서술은 각 칸의 `근거` 또는 `비고`에 적는다. 출처가 `W1-06 추가`인 값은 기존 문서에 없어 본 문서가 새로 정한 값이다.

### 3.1 구분 값

| 항목 | 허용 값 | 출처 |
|---|---|---|
| PoC 범위 | `필수` · `필수 보조` · `확장` · `확장·조건부` · `해당 없음`(W1·W5 작업) | WBS PoC 작업표 범위 열 |
| 작업 우선순위 | `P0` · `P1` · `P2` · `해당 없음` | W1-02 §3.4 |
| W1-03 검증 유형 | `데이터 접근` · `판단 근거` · `AI 해석` · `콘텐츠 활용` · `프로그램 연결` · `업무 효과` · `W1-03 미지정` (복수 선택 가능) | W1-03 §3. 기록자가 새로 정하지 않고 W1-03이 지정한 값을 옮긴다. |
| 핵심 가정 여부 | `예` · `아니오` · `W1-03 미지정` | W1-03 §5. 지정 방식은 검증 유형과 같다. |
| 데이터 구분 | `실제` · `테스트` · `Mock` · `혼합` | WBS 공통 입력. `혼합`은 W1-06 추가이며, 쓸 때는 §5-3에 항목별 구분을 명시 |
| 평가 데이터 세트 | `개발·파일럿` · `평가` | W1-03 §4 자료 분리 |
| 수행 방식 | `자동` · `수동` · `반자동` | W1-06 추가 (근거: WBS A02-02 "자동 수집과 직접 입력을 표시") |
| 외부 연동 범위 | `실제 연동` · `호출 직전 데이터` · `업로드 파일` · `수동 절차` · `Mock` · `해당 없음` | WBS 외부 연동 원칙 |
| 관리자 승인 (PoC 단위) | `필요 없음` · `승인 전` · `승인 후` · `반려` | WBS 운영 원칙 "외부 실행은 관리자 승인 전후를 구분". `필요 없음`은 W1-06 추가 |
| 판정 기준 필수 여부 | `필수` · `참고` | W1-06 추가. WBS 완료 기준과 W1-03 통과 기준에서 옮긴 기준은 모두 `필수` |

### 3.2 상태·판정 값

PoC 결과는 다음 일곱 단계로 나누어 기록한다. 서로 다른 단계의 값을 섞어 쓰지 않는다.

| 단계 | 기록 위치 | 허용 값 | 판단 대상 | 출처 |
|---|---|---|---|---|
| 실행 단계 상태 | §5-5 | `대기` · `실행 중` · `성공` · `부분 성공` · `실패` · `검토 필요` · `승인 대기` · `승인 완료` · `반려` · `보류` | 실행 1회 또는 단계 1개의 최종 시스템 상태 | WBS 공통 실행 상태 |
| 회차 결과 | §5-5 | `성공` · `부분 성공` · `실패` · `보류` | 실행 1회 또는 단계 1개의 결과 판정 | WBS 공통 결과 기준 |
| 기준 판정 | §5-6 | `충족` · `미충족` · `측정 불가` · `해당 없음` | 판정 기준 1개 | W1-06 추가 |
| 실행 상태 | §5-9 | `완료` · `보완` · `실패` · `보류` | PoC 작업 전체 | WBS 가드레일, W1-02 §6.1 |
| 기술 판정 | §5-9 | `기술 검증 완료` · `추가 검증 필요` · `외부 제약` · `검증 실패` | 기술적 목표 달성 여부 | WBS 가드레일, W1-02 §6.2 |
| 제품화 제안 | §5-9 | `Go` · `Conditional Go` · `No-Go` · `Hold` · `해당 없음` | 주 담당의 제안. 최종 판정은 W5-08 | WBS W5 판정 체계. `해당 없음`은 W1-06 추가 |
| 제품화 상태 | §5-9 | `MVP 제품화` · `조건부 제품화` · `재검증·제외` · `PoC 완료·제품화 보류` · `해당 없음` | 제품화 제안에 대응하는 상태 | WBS W5 판정 체계 |

- **제안과 상태의 대응:** 제품화 제안과 제품화 상태는 1:1로 대응한다.

  | 제품화 제안 | 제품화 상태 |
  |---|---|
  | Go | MVP 제품화 |
  | Conditional Go | 조건부 제품화 |
  | No-Go | 재검증·제외 |
  | Hold | PoC 완료·제품화 보류 |

- **`해당 없음`을 쓰는 경우:** 필수 보조 작업(B-INT-01, DE-INT-01 등)과 W5 실행형 작업은 Agent가 아니므로 제품화 제안을 `해당 없음`으로 적는다.
- **Agent 단위 종합:** 한 Agent에 PoC가 여러 개이면 PoC마다 제안을 적는다. 이를 Agent 단위로 종합하는 것은 W5-08에서 한다.
- **미착수 PoC의 기술 판정 (W1-06 추가):** W5-07 이전에 착수하지 못한 PoC는 기술 판정 칸에 `미판정(미착수)`을 임시로 쓸 수 있다.
  - W5-07에서 다음 중 하나로 확정한다. 권한·정책·데이터 제약 때문이면 `외부 제약`, 그 밖의 사유이면 `추가 검증 필요`.
  - 착수하지 않은 PoC는 `검증 실패`로 판정하지 않는다(W1-02 §3.2).
  - W5-07 완료 기준은 미판정 PoC 0건이다.

### 3.3 판정 간 일관성 규칙

| 규칙 | 내용 |
|---|---|
| R1 | 실행 상태 `완료`는 두 조건을 모두 충족할 때만 쓴다. ① 계획한 회차마다 최종 회차(§5-5 재실행 규칙)가 있다. ② 모든 기준에 기준 판정과 증빙이 기록되었다. |
| R2 | 기술 판정 `기술 검증 완료`는 세 조건을 모두 충족할 때만 쓴다. ① 실행 상태가 `완료`다. ② 필수 기준이 모두 `충족`이다(사유가 기록된 `해당 없음`은 제외). ③ §5-8 재현 결과가 `기준 판정 동일`이다. |
| R3 | 필수 기준 중 `미충족` 또는 `측정 불가`가 있으면 실행 상태는 `보완`·`실패`·`보류` 중 하나로 적고, 사유를 §5-9에 적는다. 원인을 기록한 것만으로 `완료` 처리하지 않는다. |
| R4 | 실행 상태가 `보류`이면 `기술 검증 완료`를 쓰지 않는다. 권한·정책·데이터 제약이 확인되면 `외부 제약`을, 가능성은 확인했지만 증빙이 부족하면 `추가 검증 필요`를 쓴다. 미착수 건은 §3.2 규칙을 따른다. |
| R5 | 제품화 제안 `Go`는 기술 판정이 `기술 검증 완료`일 때만 할 수 있다. 단, 기술 검증 완료가 곧 제품화 승인을 의미하지는 않는다(W1-02 §6.3). |
| R6 | `Conditional Go`와 `Hold`를 제안하면 §5-10에 보완 조건 또는 선행 조건, 담당자, 기한, 재판정 시점을 기록한다. |
| R7 | `No-Go`를 제안하면 §5-10에 제외 사유와 재검증 조건을 기록한다(WBS W5 판정 체계). |
| R8 | 회차 결과보다 기준 판정이 우선한다. 예: 3회 모두 `성공`이어도 근거 연결률이 100% 미만이면 해당 기준은 `미충족`이다. |
| R9 | 핵심 가정 여부가 `예`인데 기술 판정이 `기술 검증 완료`가 아니면, 제품화 제안은 `Hold` 또는 `No-Go`만 쓸 수 있다(W1-03 §5: 핵심 가정이 실패하거나 미검증이면 의존 본개발 Hold). |
| R10 | 필수 기준을 `해당 없음`으로 판정하면 §5-6 근거 칸에 사유를 적는다. 이 기준은 `필수 기준 충족` 집계의 분모에서 뺀다. 예: A01-01의 "접근 가능 플랫폼" 조건에 해당하지 않는 경우 |

### 3.4 누락 사유와 오류 처리

**누락 사유** (WBS 공통 필수 데이터)

- `원본 정보 없음`
- `로그인 필요`
- `접근 제한`
- `수집 실패`
- `수동 확인 필요`

**오류 종류와 기본 처리**

| 오류 종류 | 기본 처리 | 자동 재시도 | 출처 |
|---|---|---|---|
| `네트워크·API 일시 오류` | 최대 2회 자동 재시도 | 가능 (최대 2회) | WBS 오류 처리 원칙, W1-02 §5.4 |
| `호출 제한` (429 등) | Retry-After에 따라 대기한 뒤 재시도 | 가능 | W1-06 추가 (근거: W1-03 §3 1) Rate Limit). 재시도 상한은 W5-09 오류 계약에서 확정하며, 그전까지 최대 2회를 임시로 적용 |
| `로그인·전화 인증` | 자동 재시도하지 않고 사람의 확인 요청 | 불가 | WBS 오류 처리 원칙, W1-02 §5.4 |
| `접근 제한·차단` (403, CAPTCHA 등) | 사람의 확인 요청 후 수동 입력 또는 대체 데이터 사용 | 불가 | WBS 오류 처리 원칙, W1-02 §5.4, W1-03 §3 1) |
| `필수 정보 누락` | 누락 사유 기록, 수동 입력 요청 | 불가 | WBS 오류 처리 원칙, W1-02 §5.4 |
| `형식·파싱 오류` | 출력 계약 위반 내용을 기록하고, 원인을 수정한 뒤 새 회차로 실행 | 불가 | W1-06 추가 (근거: W1-03 §3 프로그램 연결) |
| `AI 출력 품질 오류` (근거 없는 주장, 핵심 수치 오류 등) | 오류 건수와 원문 대조 결과 기록 | 불가 | W1-06 추가 (근거: W1-03 §3 AI 해석) |
| `기타` | 비고에 내용 기록 | 사례별 판단 | W1-06 추가 |

- **W5-04 시나리오의 분류:** W5-04 오류 시나리오는 위 오류 종류에 다음과 같이 대응시킨다. `AI API 오류`는 호출 실패를 뜻하고, 응답 내용이 틀린 `AI 출력 품질 오류`와는 구분한다.

  | 이미지 실패 | 원인에 따라 `네트워크·API 일시 오류` 또는 `접근 제한·차단` |

### 3.5 표기 규칙

- **빈칸 금지:** 칸을 비워 두지 않는다. 값이 없으면 다음 중 하나를 적는다.
  - `없음`: 해당 사항이 0건일 때
  - `해당 없음`: 이 PoC에 적용되지 않을 때
  - `측정 불가(사유)`
  - `누락(누락 사유)`
- **시각:** KST, `YYYY-MM-DD HH:mm` 형식으로 적는다.
- **처리 시간:** 초(s) 단위로 적는다. 사람의 수동 작업 시간은 분(min) 단위로 따로 적는다.
- **AI 비용:**
  - §5-5에는 청구 통화 그대로 통화 코드와 함께 적는다(예: `0.042 USD`).
  - §5-0과 §6.2에는 비교를 위해 원화(KRW)로 환산한 값을 적고, 환율과 기준일을 비고에 적는다.
- **비율:** `분자/분모 (백분율)` 형식으로 적는다(예: `29/30 (96.7%)`).
- **상한 비교:**
  - WBS의 처리 시간·AI 비용·실패율·수동 개입 상한은 **상품 1건 전체 흐름**과 **통합 실행**을 기준으로 한다.
  - 따라서 상한 비교는 통합 실행 기록(W5-01·W5-02·W5-06)에만 적는다. 상한이 정해지기 전에는 `상한 미정`, 정해진 뒤에는 `이내` 또는 `초과`로 적는다.
  - 그 밖의 PoC는 수치를 참고값으로만 기록하고, 상한 비교 칸에는 `해당 없음`을 적는다.
- **ID:** 실행 ID·상품 ID·결과 버전의 형식은 W1-04 공통 데이터 구조를 따른다.
- **증빙 링크:** 저장소 상대 경로 또는 만료되지 않는 URL로 적는다. 개인 메신저 링크와 로컬 경로는 증빙으로 인정하지 않는다.
- **보안·권리:**
  - API Key·비밀번호·세션 토큰은 기록하지 않는다.
  - 리뷰의 개인정보는 비식별화한다.
  - A02-03 사용 범위 점검표에서 `저장`이 불가 또는 `확인 필요`로 판정된 자료는 파일로 저장하지 않고, URL과 상태만 기록한다.
  - 판매 콘텐츠 재사용 여부는 같은 점검표의 판정을 따른다.

**작성 규칙**

- **회차:** 평가 단위 1개를 1회 실행한 것을 회차 1개로 센다. 반복 실행은 `반복` 번호로 구분한다.

  - 판정과 변동 폭 계산(예: B-INT-01 3회 비교)에는 각 반복의 **최종 회차**를 쓴다.
- **통합 실행 (W5-01·W5-02 등):** 한 회차 안에서 Agent 단계마다 1행씩 기록하고, 마지막 행의 `Agent·단계`에 `전체`를 적는다.
  - 두 표는 `회차 + Agent·단계`를 키로 연결한다.
- **다른 기록의 실행 재사용:** W5-06처럼 다른 기록의 실행을 다시 쓰면, `증빙` 열에 원 기록 링크와 원 실행 ID를 적는다.
- **집계 (§5-0 회차 결과·실패율):**
  - 단일 PoC는 회차 단위로 센다.
  - 통합 실행은 `전체` 행만 센다.
  - 실패율은 재실행을 포함한 전체 회차를 분모로 한다.

## 6. PoC 결과 비교표

모든 PoC 기록의 §5-0 요약을 모은 표다. 한 화면에서 비교할 수 있도록 **판정 뷰**와 **수치 뷰** 두 표로 나누고, 두 표는 PoC ID로 연결한다.

- **갱신 시점:** W2-W4 동안 매주 금요일 시연 전에 갱신한다.
- **용도:** W5-07 PoC 의사결정표의 입력으로 사용한다.
- **값이 다를 때:** 비교표와 PoC 기록의 값이 다르면 PoC 기록을 기준으로 바로잡는다.

### 6.1 판정 뷰

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| `<A02-01>` | `<A02>` | `<필수>` | `<B / C>` | | | `<n/m>` | | | | | | | | `<링크>` |

  - 같은 Agent 안에서는 필수 기준 충족 수와 기술 판정을 비교한다.
  - 처리 시간·AI 비용·실패율·수동 개입은 `평가 단위`가 같은 PoC끼리만 비교한다.
  - 상한과의 비교는 통합 실행 기록에만 적용한다(§3.5).
- **승인 전 행:** `검토 결과`가 `승인`이 아닌 행은 W5-07 판정 입력으로 쓰기 전에 검토를 마친다.

## 7. 검토 체크리스트

검토 담당은 아래 항목을 확인하고, 결과를 §5-11에 기록한다.

**기준과 기록**

1. 판정 기준과 기준 버전이 첫 실행 전에 기록되었고, 이후 변경은 §5-12에 `목표 변경`으로 남아 있다.
2. WBS 완료 기준과 W1-03 기준이 모두 §5-2에 `필수` 기준 ID로 나뉘어 있다. 각 기준에 허용 오류·실패 시 처리·필수 증빙이 있고, §5-6에 같은 ID의 결과가 있다.
3. 모든 회차에 실행 ID·상품 ID(또는 `해당 없음` 사유)·평가 단위 ID·데이터 구분·결과 버전·증빙 링크가 있다.
4. 재실행 회차에는 재실행 대상이 적혀 있고, 원 회차가 지워지지 않았다.
5. 통합 실행이면 다음 세 가지가 모두 기록되어 있다.
   - Agent 단계마다 행이 있다.
   - 이전 단계의 결과 버전이 연결되어 있다.
   - 측정값 표가 단계별로 대응한다.

**데이터와 오류**

6. 실제·테스트·Mock 데이터 구분이 입력 데이터, 회차 로그, 판정의 실제·Mock 범위에서 서로 일치한다.
7. 필수 데이터 누락이 정해진 누락 사유로 기록되었다.
8. 실패·부분 성공 회차마다 §5-7에 실패 단계·원인·처리 결과·다음 행동이 있다.

**재현성**

9. 다음 항목이 재현할 수 있는 수준으로 기록되었다: 소스 커밋, 실행 명령, 지시문 버전, 모델 버전, 디코딩 설정, 정답안 버전.
10. 주 담당이 아닌 팀원이 재현을 확인했다.

**승인과 판정**

11. 외부 실행의 관리자 승인 상태가 기록되었고, 승인 없이 외부 단계가 실행된 사례가 없다.
12. 실행 상태·기술 판정·제품화 제안·제품화 상태가 §3.3 일관성 규칙 R1 ~ R10을 위반하지 않는다.
13. `Conditional Go`·`Hold`·`No-Go`에는 R6·R7이 요구하는 조건·사유·담당자·기한·재판정 시점이 있다.

**보안과 정합성**

14. 기록이나 증빙에 비밀 정보, 개인정보, 저장 불가 또는 `확인 필요` 자료가 포함되지 않았다.
15. §5-0 요약, §6 결과 비교표, 본문의 값이 서로 일치한다.

### v0.2 주요 반영 사항

- WBS 「PoC 기록 양식」의 관리자 승인, 제품화 상태와 결정 사유, 테스트 조건, 후속 작업 항목을 반영
- WBS 공통 입력·출력의 `경고·확인 필요`, `이전 단계 결과 버전`을 추가
- 실행 상태를 4개 값으로 정리
- §6 비교표를 판정 뷰와 수치 뷰로 분리
- 통합 실행의 단계별 행 규칙을 추가
- 오류 처리 원칙을 원문 기준으로 복원
- W1-03 연결 칸과 W5-06 수치 칸을 추가

### v0.3 주요 반영 사항

**통합 실행 기록**

- §5-5 측정값 표에 `Agent·단계` 열을 추가하고, 두 표를 `회차 + Agent·단계`로 연결
- 통합 실행 집계는 `전체` 행 기준으로 정함

**실행 로그 열 추가**

- 상품 ID: WBS "모든 실행에 실행 ID와 상품 ID"
- 실행 단계 상태: WBS 공통 실행 상태
- 승인 상태
- 재실행 대상

**판정 기준**

- 상한 비교를 통합 실행 기록에만 적용하고, 그 밖의 PoC는 참고값으로 기록. 수치 비교는 같은 평가 단위끼리만 함
- 핵심 가정 규칙(R9)과 필수 기준 `해당 없음` 처리 규칙(R10)을 추가
- 기준의 `필수·참고` 값을 고정
- `실패 시 처리` 열과 `필수 산출물·증빙`을 추가

**값 체계와 출처**

- 비교 방식을 규칙만·AI만·결합으로 분리
- 검증 유형과 핵심 가정은 W1-03 지정값을 옮겨 적도록 바꿈(복수 선택 허용, 미지정 표시)
- 미착수 기록의 최소 작성 범위와 W5-07 확정 기준을 추가
- 필수 보조·W5 작업의 제품화 제안 `해당 없음`을 허용
- `W1-06 추가` 출처 표시를 보완
- `사람 확인 후 재개` 처리 결과와 W5-04 시나리오 대응표를 추가
- `AI 출력 오류`를 `AI 출력 품질 오류`로 이름 변경

**문서 정리**

- 상한 담당을 근거 없이 지정한 부분을 삭제
- 이미지 저장 규칙을 A02-03 점검표 판정을 따르도록 수정
- 미검증 범위 기록 위치를 §5-9 하나로 통일
- 기록 상태와 검토 결과의 이름을 통일
- 비교표에 `핵심 가정`과 `검토 결과` 열을 추가
- AI 비용 비교값을 원화 환산값으로 통일
